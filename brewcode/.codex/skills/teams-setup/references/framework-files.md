# Framework Files Reference

Templates for `.codex/teams/{TEAM_NAME}/` directory. All placeholders (`{TEAM_NAME}`, `{DATE}`,
`{LAST_UPDATED}`, `{PLUGIN_VERSION}`, `{N}`, `{CWD}`) replaced at creation time.

| Placeholder | Value | Where it comes from |
|-------------|-------|---------------------|
| `{PLUGIN_VERSION}` | `X.Y.Z` | the `PLUGIN_VERSION:` line Phase 1's `detect-mode.sh` already printed -- NEVER typed by hand, never a template version |
| `{LAST_UPDATED}` | `YYYY-MM-DD` | the `LAST_UPDATED:` line from the same output (`date +%F`) |
| `{DATE}` | `YYYY-MM-DD` | creation date; written once, never rewritten by UPGRADE |

team.md uses apply_patch. trace.jsonl is **append-only** via Bash (`trace-ops.sh add`).

---

## 1. team.md

```markdown
# Team: {TEAM_NAME}

| Field | Value |
|-------|-------|
| Created | {DATE} |
| Version | {PLUGIN_VERSION} |
| Generated by | brewcode:teams-setup |
| Last update | {LAST_UPDATED} |
| Agents | {N} |
| Project | {CWD} |

## Agents

| Agent | Domain | Mission | Status | Updated | Kind | Version |
|-------|--------|---------|--------|---------|------|---------|
| intent-guard | -- | Anti-drift check: what was ASKED vs what was DELIVERED | active | {LAST_UPDATED} | review-only | {PLUGIN_VERSION} |
```

> The `Agent` column MUST stay first (`verify-team.sh` reads it as field 2 of the row). `Kind` and
> `Version` are trailing columns -- append any future column at the END, never before `Agent`.

> The three metadata rows are `Version`, `Generated by`, `Last update`, in exactly that order and
> adjacent -- the artifact-metadata standard's header-table carrier. `Created`, `Agents`, `Project` are
> this skill's own extra rows; keep them outside the trio, never interleaved.

> `Version` is per-agent on purpose: UPGRADE rewrites only the rows it actually touches, so a roster
> can legitimately hold agents generated under different plugin versions and the table shows which.
> The header-table `Version` row is the version of the LAST write to `team.md` itself.

Status values: `active`, `inactive`, `updating`, `disabled`, `removed`

`disabled` is written by `$brewcode:teams-setup disable`: the agent file is parked as
`.codex/agents/{name}.toml.disabled`, so Codex no longer discovers it, but the body and the whole
team dir are intact and `enable` restores both the file and the `active` status. Distinct from
`inactive` (live agent, zero trace activity) and from `removed` (file deleted).
Kind values: `domain` (default, may be left blank), `review-only`

`intent-guard` is a mandatory row in EVERY team: review-only, shared with `$brewcode:superreview-setup`,
outside the `Agents | {N}` domain count, and never removed by UPDATE/CLEANUP.

## 2. trace.jsonl

Empty file at creation. Agents append via `trace-ops.sh add`.

Format: JSONL — one JSON object per line:

| Field | Required | Description |
|-------|----------|-------------|
| `ts` | auto | ISO8601 UTC timestamp |
| `sid` | yes | Session ID, 8 chars |
| `src` | yes | Agent name |
| `k` | yes | `track` / `issue` / `insight` |
| `s` | track | `took` / `refused` / `completed` / `failed` |
| `sev` | issue | `low` / `medium` / `high` / `critical` |
| `cat` | insight | `pattern` / `architecture` / `performance` / `security` / `convention` / `debt` |
| `txt` | yes | Text, max 100 chars (auto-truncated by trace-ops.sh) |
