# Brewtools Overview

Brewtools is a utility plugin for Claude Code: token-efficient text optimization, AI-artifact removal, secrets scanning, SSH management, GitHub Actions deployment, and opt-in guards for subagents. The utility skills work with no setup; the `-setup` skills install their mechanism first.

**13 skills · 3 agents · 1 registered hook command.**

## Install

<InstallPrompt plugin="brewtools" mode="install" />

## What you get

- **Text and security:** `text-optimize`, `text-human`, `secrets-scan`.
- **Ops:** `ssh`, `deploy`, `plugin-update`, `provider-switch`, `context-slim`.
- **Opt-in guards:** `manager-setup` (delegation wall), `agent-deadline-setup`, `agent-return-setup`, `agent-router-setup` (experimental).
- **Task board:** `task-board-setup`, a file-based Kanban with anti-drift timers.

Per-skill detail: [Skills](/brewtools/skills/). Agents: `text-optimizer`, `ssh-admin`, `deploy-admin` ([Agents](/brewtools/agents/)).

## Example

```
/brewtools:text-optimize -s docs/
/brewtools:secrets-scan --fix
/brewtools:manager-setup install level strict
```

The manager hard wall fails closed: an unparseable payload, a missing or corrupt `state.json` and an unrecognised MCP tool name are denied, and a registered guard script that is missing blocks every tool call (Claude Code 2.1.295 or newer). Leave the wall with `disable` or `uninstall`, never by deleting files.

<ModPromo variant="strip" />

## How it fits

Each skill is self-contained and needs no Brewcode or Brewdoc. Brewtools covers text, ops and subagent control; [Brewcode](/brewcode/overview/) covers skill and agent authoring, semantic search and the setup dashboard. Both install from the same `claude-brewcode` marketplace and operate independently. The prompt codewords `++m ++a ++rr ++r +++` come from the [placeholders mod](/mods/placeholders/), not this plugin.

<Spoiler id="naming-rules" title="Naming and invocation rules">

A `-setup` suffix marks a skill that installs a mechanism you afterwards use instead of the skill. Every `-setup` skill shares one mode set, in this order: `status | install | upgrade | enable | disable | uninstall | purge`; `task-board-setup` defaults to `install` when absent, the others to read-only `status`. `text-optimize` and `text-human` are model-invocable; the rest run only when you type them (see the [FAQ](/faq/#auto-invoke)).

</Spoiler>

<Spoiler id="task-methodology" title="Task methodology and anti-drift">

Shared methodology, hourly anti-drift timers and the `+++` plan hook are described on [Task Board Setup](/brewtools/skills/task-board-setup/).

</Spoiler>

<Spoiler id="artifact-metadata-note" title="Artifact metadata">

Every `-setup` skill stamps what it writes with `version`, `content_version` and `generated_by`; the five fields and five carriers are documented once in [Brewcode: Artifact metadata](/brewcode/overview/#artifact-metadata). `/brewcode:setup-status` reads the stamps back across all eleven `-setup` skills and reports installs running on an older brewtools version; the fix is that skill's own `upgrade` mode.

</Spoiler>

<Spoiler id="plugin-variable" title="Plugin variables">

`${CLAUDE_PLUGIN_ROOT}` and `${CLAUDE_SKILL_DIR}` are text substitutions Claude Code performs on the prompt, not environment variables. Skills use `${CLAUDE_SKILL_DIR}` for their own files; agent definitions get `${CLAUDE_PLUGIN_ROOT}` substituted at spawn and cannot read it as a shell variable.

</Spoiler>

<Spoiler id="plugin-structure" title="Plugin structure and hooks">

`brewtools/` holds `skills/` (13), `agents/` (3) and `hooks/`. The only registered hook is `session-start.mjs` (SessionStart): it prints the wall notice and the exit (`/brewtools:manager-setup disable`) when armed, otherwise it is silent. `hardmode-guard.mjs` is a template that `manager-setup` copies into a project.

</Spoiler>
