# plugin-update

<Badge text="sonnet" /> <Badge text="4 modes" /> <Badge text="user-invoked" />

Checks, installs and updates the brewcode suite (brewcode, brewdoc, brewtools, brewui) in one command. Installed mods (`brewmod-placeholders`, `brewmod-plan-effort`) are checked and updated too, never installed: a mod that is not installed gets no row and never shows as missing.

## Quick reference

| Field | Value |
|-------|-------|
| Command | `/brewtools:plugin-update` |
| Arguments | `[prompt] [check\|update\|all]` — free-form prompt first; no args = interactive |
| Model | sonnet |
| Output | Version table, change summary, reload notice |

## Modes

| Situation | Command |
|-----------|---------|
| Walk through each decision interactively | `/brewtools:plugin-update` |
| Just check versions, change nothing | `/brewtools:plugin-update check` |
| Update what is outdated, skip missing | `/brewtools:plugin-update update` |
| Install missing + update all, no prompts (new machine, CI) | `/brewtools:plugin-update all` |

## Example

```bash
/brewtools:plugin-update check
```

| Plugin | Installed | Latest | Status |
|--------|-----------|--------|--------|
| brewcode | X.Y.0 | X.Y.1 | `⬇️ update available` |
| brewdoc | X.Y.1 | X.Y.1 | `✅ current` |
| brewtools | — | X.Y.1 | `❌ missing` |
| brewui | X.Y.1 | X.Y.1 | `✅ current` |
| brewmod-placeholders | X.Y.0 | X.Y.1 | `⬇️ update available` |

Versions are placeholders. Legend: `✅` current, `⬇️` update available, `❌` missing, `❓` unknown.

<Callout type="warning">
Run `/reload-plugins` or restart the session after any install or update. Claude Code reads skill and agent definitions once at startup, so changes take effect only after a reload.
</Callout>

## How it works

<Steps>
  <li><div><strong>Discover</strong><p>Lists installed plugins with `claude plugin list --json`, or a script fallback on older CLIs.</p></div></li>
  <li><div><strong>Fetch latest</strong><p>Reads published versions from GitHub; on a network failure the run stays read-only.</p></div></li>
  <li><div><strong>Status table</strong><p>Prints the table above. `check` stops here.</p></div></li>
  <li><div><strong>Install missing</strong><p>Suite plugins only, asked or automatic (`all`); skipped for `update`.</p></div></li>
  <li><div><strong>Update outdated</strong><p>One marketplace refresh, then one `claude plugin update` per selected plugin at its own scope.</p></div></li>
  <li><div><strong>Auto-update hint</strong><p>Points to `/plugin` → Marketplaces; the skill never edits settings files.</p></div></li>
  <li><div><strong>Prune</strong><p>Previews orphaned dependencies and removes them only after confirmation.</p></div></li>
  <li><div><strong>Reload notice</strong><p>Always printed, with a summary of installed, updated, skipped and failed items.</p></div></li>
</Steps>

## Technical details

<Spoiler id="internals" title="Internals: discovery, update chain, gates">

**Discovery.** `claude plugin list --json` (CC 2.1.163+) returns `id`, `version`, `scope`, `enabled`, `installPath`, `installedAt`, `lastUpdated`, optional `mcpServers`, and `projectPath` on project/local rows only. `version` may be `"unknown"` for locally loaded plugins. Inside a session the call is prefixed with `unset CLAUDECODE &&`. If it errors, returns nothing or invalid JSON, `scripts/discover-plugins.sh` reads `settings.json` (`CLAUDE_CONFIG_DIR`, default `~/.claude`) and walks the cache (`CLAUDE_CODE_PLUGIN_CACHE_DIR`, default `<config dir>/plugins/cache/`). If both fail, the inventory is reported unknown and install, update and prune are skipped.

**Update chain.** `--scope` is always passed from the plugin's own discovery row, because CLIs before 2.1.281 read an omitted scope as `user` and update the wrong instance:

```bash
claude plugin marketplace update claude-brewcode
claude plugin update <id> --scope <scope>
(cd "<projectPath>" && claude plugin update <id> --scope <scope>)
```

```bash
claude plugin update brewcode@claude-brewcode --scope user
claude plugin update brewdoc@claude-brewcode --scope user
claude plugin update brewtools@claude-brewcode --scope user
claude plugin update brewui@claude-brewcode --scope user
```

The second block is the full suite at `user` scope; an installed mod follows the same pattern, for example `brewmod-placeholders@claude-brewcode`. Project and local rows run from their own `projectPath`. A missing directory is reported as an orphan install with `mkdir -p "<projectPath>" && cd "<projectPath>" && claude plugin uninstall <id> --scope <scope>` as the removal command. A failed command is reported and the run continues.

**Prune.** `claude plugin prune --dry-run --scope <scope>` once per scope seen, then `claude plugin prune --scope <scope> -y`. The `-y` is mandatory: the Bash tool has no TTY, and a bare `prune` removes nothing yet exits 0. Plugins installed directly are never touched.

**Gates.** `AskUserQuestion` offers options only: install missing, update outdated, auto-update hint, prune. `check` stops before all of them; `update` auto-picks "Update all" and skips the hint and prune; `all` auto-installs, auto-updates, auto-picks "Prune listed". Mods are never offered for install: the summary prints their `claude plugin install <mod>@claude-brewcode` command for you to run.

**No delegation.** The skill spawns nothing; discovery, the chain and the gates run in the main conversation so you see every command.

**Claude summarizes instead of running?** Paste: _"Execute every `claude plugin ...` command shown above using the Bash tool. Do not describe, run each command and show full output."_

</Spoiler>
