# ssh — manage servers

<Badge variant="primary" text="opus" /> <Badge variant="accent" text="human-invoked" />

Connects to Linux servers, discovers what runs there and executes your requests, classifying every command by risk. Setup writes `~/.ssh/config` and generates an `ssh-admin` agent with the server inventory baked in.

## Quick reference

| Field | Value |
|-------|-------|
| Command | `/brewtools:ssh` |
| Arguments | `[prompt] [setup\|connect\|configure\|update-agent]` |
| Model | opus |
| Config | `CLAUDE.local.md` (gitignored, never committed) |
| Agent | [ssh-admin](/brewtools/agents/ssh-admin/) |

## Modes

| Mode | Does |
|------|------|
| `setup` | Add a server: key auth, `~/.ssh/config` entry, discovery, agent |
| `connect` | Connect to the configured server, or ask which |
| `configure` | Apply a config change under the same classification |
| any other text | Execute: plan, classify, run after confirmation |
| `update-agent` | Re-discover up to 3 servers, refresh `ssh-admin` |

## Example

```bash
/brewtools:ssh check disk space and docker status on vps-main
```

Read-only checks run without prompts. A restart or removal asks for confirmation first.

## How it works

<Steps>
  <li><div><strong>Detect mode</strong><p>An explicit token wins; otherwise keywords decide. Empty input means setup with no servers, execute otherwise.</p></div></li>
  <li><div><strong>Check environment</strong><p>Scans SSH keys, `ssh-agent`, `~/.ssh/config` and the server list in `CLAUDE.local.md`.</p></div></li>
  <li><div><strong>Connect and discover</strong><p>Tries keys (ed25519, rsa, ecdsa), reads OS, Docker, disks, ports and services within 30 s.</p></div></li>
  <li><div><strong>Persist</strong><p>Saves inventory to `CLAUDE.local.md`, gitignores it, generates `.claude/agents/ssh-admin.md`.</p></div></li>
  <li><div><strong>Classify, confirm, report</strong><p>READ and CREATE run freely; MODIFY and SERVICE ask; DELETE and PRIVILEGE warn and always ask.</p></div></li>
</Steps>

## Good to know

<Callout type="caution">
Every destructive command requires explicit confirmation, even when chained with safe ones. Compound requests are split into individually classified steps.
</Callout>

- sshd, port and firewall changes pass a 5-step lockout gate: allow-new, `sshd -t`, reload, prove a new session, then deny-old.
- Password prompts cannot be answered by Claude Code: use `! ssh deploy@your-server`.

## Technical details

<Spoiler id="safety-classification" title="Safety classification and limits">

Risk classes (READ, CREATE, MODIFY, SERVICE, DELETE, PRIVILEGE) and their gates: [ssh-admin safety classes](/brewtools/agents/ssh-admin/#safety-rules).

| Rule | Limit |
|------|-------|
| Connection timeout | 10 s (`ConnectTimeout=10 BatchMode=yes`) |
| Discovery script | 30 s total |
| Single SSH command | 60 s, then killed and reported |
| Inline SSH commands (Phase 5) | 5, more are delegated to `ssh-admin` |
| SSH calls per invocation | 15 in total, then stop and report |
| Key auth attempts | 3, then ask |
| AskUserQuestion per phase | 3 max |

Individual commands run through the shared `ght 60 ssh ...` helper in `skills/deploy/scripts/lib/deploy-common.sh`, which uses `timeout`, `gtimeout` or a Bash watchdog.

</Spoiler>

<Spoiler id="config-files" title="Config files and host keys">

| File | Purpose |
|------|---------|
| `CLAUDE.local.md` | Server inventory: alias, host, user, key, OS, Docker |
| `~/.ssh/config` | Host blocks; existing blocks are never overwritten |
| `.claude/agents/ssh-admin.md` | Generated agent; refresh with `update-agent` |

For a new or changed host key, compare the scanned SHA256 fingerprint with an out-of-band record before trusting it. A connection failure alone is not permission to erase known_hosts entries. Environment values are read only when named and needed; env dumps and credential files are never printed. If a helper script fails, the skill retries inline, then reports `SCRIPT_ERROR` / `EXIT_CODE` / `STDERR` / `PHASE` and stops.

</Spoiler>

<Spoiler id="delegation" title="Delegation">

A bounded multi-command job on one host goes to [ssh-admin](/brewtools/agents/ssh-admin/) (the plugin's `brewtools:ssh-admin` when the project has no generated agent), one agent per host, briefed with the six fields in [Delegation](/brewcode/skills/#delegation). Confirmation gates stay in the main conversation; the agent returns exact approval envelopes and runs only the APPROVED ids.

</Spoiler>
