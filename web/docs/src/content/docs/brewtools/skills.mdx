# Skills

Skills (recipes) are slash commands that define *what* to do. Brewtools includes 12 skills
focused on text processing, security scanning, SSH management, deployment, plugin management, subagent budgeting, and session orchestration -- each works independently with no prior setup required.

## Summary table

| # | Skill | Command | Model | Purpose |
|---|-------|---------|-------|---------|
| 1 | agent-deadline | `/brewtools:agent-deadline` | sonnet | Install a soft wall-clock budget for subagents — warns at 80%, blocks non-finalizing tools past 100% |
| 2 | agent-router | `/brewtools:agent-router` | sonnet | EXPERIMENTAL. Denies a generic subagent spawn when a real project/plugin expert owns the task, naming it |
| 3 | deploy | `/brewtools:deploy` | opus | GitHub Actions deployment: workflows, releases, GHCR, CI/CD with safety gates |
| 4 | manager | `/brewtools:manager` | sonnet | Manager mode: installs a hard delegation wall into this project — on, off, uninstall, status, level, edit, reset — and explains/customizes codewords `++m`, `++a`, `++rr`, `++r` |
| 5 | plugin-update | `/brewtools:plugin-update` | sonnet | Checks, installs, updates Claude Code plugins |
| 6 | provider-switch | `/brewtools:provider-switch` | opus | Configure alt API providers: DeepSeek, Z.ai/GLM, Qwen, MiniMax, OpenRouter |
| 7 | secrets-scan | `/brewtools:secrets-scan` | sonnet | Scans git-tracked files for leaked secrets |
| 8 | ssh | `/brewtools:ssh` | opus | SSH server management — connect, configure, deploy, administer Linux servers with safety gates |
| 9 | task-board-init | `/brewtools:task-board-init` | opus | Generator: deploys a file-based Kanban into any repo via multi-agent analysis, plus an optional gated CLAUDE.md-optimization pass |
| 10 | text-human | `/brewtools:text-human` | sonnet | Humanizes code, docs, articles, reddit/chat, javadoc — strips AI artifacts, fixes unicode, fits register |

| 12 | think-short | `/brewtools:think-short` | sonnet | Installs or removes the think-short terse-mode hooks |

## How these skills delegate

Nine of the eleven spawn subagents, and they all follow the same sizing rule: **one subagent = one bounded unit** — one deliverable, roughly 5 files and 10 steps. A big task handed to one agent is an agent gone for an hour: you cannot observe it, you cannot correct it, and it usually drifts off-target. Bigger work is split into N tasks fanned out in a single message.

Every spawn prompt carries six fields — GOAL, ROLE, SCOPE, CONTEXT, CONSUMER, DONE. A bare one-line task is never enough.

| Skill | One bounded unit is... |
|-------|------------------------|
| [agent-deadline](/brewtools/skills/agent-deadline/) | one mode-and-scope combination — a single `brewcode:hook-creator` spawn per combination |
| [deploy](/brewtools/skills/deploy/) | one deliverable, one repo, one environment — confirmation gates stay in the main conversation |
| [provider-switch](/brewtools/skills/provider-switch/) | one provider — five research agents, one message |
| [secrets-scan](/brewtools/skills/secrets-scan/) | one chunk of the file list — a bigger repo gets more chunks, not bigger ones |
| [ssh](/brewtools/skills/ssh/) | one deliverable on one host — DELETE/PRIVILEGE approval happens before any spawn |
| [task-board-init](/brewtools/skills/task-board-init/) | one doc group — same rule at both spawn points |
| [text-human](/brewtools/skills/text-human/) | one block of files from the commit or folder |
| [text-optimize](/brewtools/skills/text-optimize/) | one file — a folder run is split one file per agent |
| [think-short](/brewtools/skills/think-short/) | one install target — a wider request is one task per target |

[plugin-update](/brewtools/skills/plugin-update/) and [manager](/brewtools/skills/manager/) spawn nothing — neither carries `Task` in its `allowed-tools`, so every command runs in front of you.
