# Skills

Skills (recipes) are slash commands that define *what* to do. Brewtools includes 13 skills
focused on text processing, security scanning, SSH management, deployment, plugin management, subagent budgeting, and session orchestration -- each works independently with no prior setup required.

<Callout type="note" title="The -setup naming rule">
  A `-setup` suffix marks a skill that installs a persistent mechanism: hooks, a generated board, or a delegation wall. Recurring tools keep bare names such as text-optimize, deploy, and ssh. Setups share status, install, upgrade, enable, disable, uninstall, and purge. Use explicit modes; manager-setup defaults to status. Each page documents additional arguments and exact removal boundaries.
</Callout>

## How these skills delegate

Delegated work follows the same sizing rule: **one subagent = one bounded unit** — one deliverable, roughly 5 files and 10 steps. Bigger work is split into bounded tasks and independent owners work in parallel.

Every spawn prompt carries six fields — GOAL, ROLE, SCOPE, CONTEXT, CONSUMER, DONE. A bare one-line task is never enough.

| Skill | One bounded unit is... |
|-------|------------------------|
| [agent-deadline-setup](/brewtools/skills/agent-deadline-setup/) | one mode-and-scope combination — a single `brewcode:hook-creator` spawn per combination |
| [agent-return-setup](/brewtools/skills/agent-return-setup/) | one mode-and-scope combination — a single `brewcode:hook-creator` spawn per combination |
| [agent-router-setup](/brewtools/skills/agent-router-setup/) | one mode — a single `brewcode:hook-creator` spawn per mode |
| [context-slim](/brewtools/skills/context-slim/) | one file — a single `text-optimizer` spawn per file, all in one message |
| [deploy](/brewtools/skills/deploy/) | one deliverable, one repo, one environment — confirmation gates stay in the main conversation |
| [provider-switch](/brewtools/skills/provider-switch/) | one provider — five research agents, one message |
| [secrets-scan](/brewtools/skills/secrets-scan/) | one chunk of the file list — a bigger repo gets more chunks, not bigger ones |
| [ssh](/brewtools/skills/ssh/) | one deliverable on one host — DELETE/PRIVILEGE approval happens before any spawn |
| [task-board-setup](/brewtools/skills/task-board-setup/) | one doc group — same rule at both spawn points |
| [text-human](/brewtools/skills/text-human/) | one block of files from the commit or folder |
| [text-optimize](/brewtools/skills/text-optimize/) | one file — a folder run is split one file per agent |

[plugin-update](/brewtools/skills/plugin-update/) runs its update commands in the main conversation. Manager-setup can delegate a task while keeping wall configuration in the main session.

Task-board prepares methodology, base work units, and a complete unique prompt for every accepted task before implementation. The main session manages one timer per active top-level task, hourly unless you override it; child work units share the parent timer. Planning remains read-only, including when standalone `+++` adds a future timer step.

<Callout type="warning" title="v6 hardening">
  The `manager-setup` wall moved from a denylist to a strict per-binary allowlist that fails closed on any unrecognized flag, and closed four further bypasses: `git diff --output=`, `git branch -D`, `gh issue comment --body`, `find -fprint0`. Every spawned subagent lost `AskUserQuestion` (removed in Claude Code 2.1.233) -- a destructive or privileged step now returns a `## APPROVAL REQUIRED` envelope instead of asking directly.
</Callout>
