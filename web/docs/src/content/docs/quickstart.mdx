# Quick Start

Establish project conventions and domain agents, then prepare a task board, specification and
project-tailored review skill. Run setup generators in separate sessions.

<Callout type="note" title="Before you begin">
  Make sure Claude Code and the brewcode plugin are installed.
  If not, follow the instructions in <a href="/installation/">Installation</a>.

  A skill whose name ends in `-setup` installs a mechanism you use afterwards instead of the skill itself; recurring tools keep bare names. The full ordered list lives in [Full Setup](/full-setup/).

  Distributed plugin skills require your explicit command. Generated project skills can be model-invocable. Each setup generator works best in its own fresh session.
</Callout>

## Full workflow

<Steps>
  <li class="step step-primary">
    <div>
      <strong>Install the workflow plugins</strong> <Badge variant="primary" text="plugin install" />
      <p>Add the marketplace and install Brewcode plus Brewtools for the task board:</p>
      <pre><code>claude plugin marketplace add https://github.com/kochetkov-ma/claude-brewcode
claude plugin install brewcode@claude-brewcode
claude plugin install brewtools@claude-brewcode</code></pre>
      <p>This step runs once per machine. Reload with <code>/reload-plugins</code> if already inside a session.</p>
    </div>
  </li>
  <li class="step step-primary">
    <div>
      <strong>Set up project conventions</strong> <Badge variant="primary" text="/brewcode:convention-setup" />
      <pre><code>/brewcode:setup-status
/brewcode:convention-setup install</code></pre>
      <p><strong>What happens:</strong> parallel agents analyze each architectural layer, extract etalon
      classes, coding, testing and architecture patterns, and write them into <code>.claude/convention/</code> with reversible loading guidance.</p>
      <p>Follow the setup dashboard's order: search foundation when applicable, then conventions before teams and review setup. <strong>Result:</strong> a written project reference for later agents.</p>
    </div>
  </li>
  <li class="step step-primary">
    <div>
      <strong>Create a domain agent team</strong> <Badge variant="primary" text="/brewcode:teams-setup" />
      <pre><code>/brewcode:teams-setup install core "one agent per bounded context, plus a migrations specialist"</code></pre>
      <p>Generates 5-20 project-specific agents with self-selection logic and performance tracking.
      Use the convention foundation when generating the team. To remove a team later,
      name it: <code>uninstall core</code>, or <code>purge core</code> to drop its archive and trace
      files too.</p>
    </div>
  </li>
  <li class="step step-primary">
    <div>
      <strong>Set up the task board</strong> <Badge variant="primary" text="/brewtools:task-board-setup" />
      <p>Run it once per repo and explicitly select the optional spec + design layer when asked:</p>
      <pre><code>/brewtools:task-board-setup install . "one lane per service"</code></pre>
      <p>Create the task first, then resolve that existing task by its unique title:</p>
      <pre><code>/task-board add "Implement JWT authorization with role-based access"
/task-spec "Implement JWT authorization with role-based access"</code></pre>
      <p>The board returns the actual task ID; use that ID with <code>/task-spec</code> if titles overlap. Task-spec requires an existing task record and does not create one. If the spec layer was omitted, run task-board setup's <code>upgrade</code> and select it before invoking task-spec.</p>
      <p><strong>What happens:</strong> <code>task-board-setup</code> analyzes the repo with parallel agents and
      deploys a file-based Kanban plus a project-tailored <code>/task-spec</code> skill. <code>/task-spec</code>
      researches the codebase, asks clarifying questions, and fans out to domain agents for system design.</p>
      <p><strong>Result:</strong> a board with shared domain methodology and a task with its own methodology, spec and design under <code>.claude/features/</code>. When a top-level task becomes active, the main session's task-board announces and creates its unique hourly session anti-drift cron, with a user-selected cadence or opt-out. Delivered ticks reconcile the graph and report progress; timers depend on the active session and runtime limits.</p>
    </div>
  </li>
  <li class="step step-primary">
    <div>
      <strong>Generate a deep review skill</strong> <Badge variant="primary" text="/brewcode:superreview-setup" />
      <pre><code>/brewcode:superreview-setup install "QUICK depth; gate on the existing build and lint commands"</code></pre>
      <p><strong>What happens:</strong> analyzes your codebase and conventions, then generates a
      project-tailored quorum review skill that merges code review and standards checking
      into one reusable skill installed locally at <code>.claude/skills/</code>.</p>
      <p><strong>Result:</strong> a custom review skill ready to invoke any time you need a deep,
      project-aware code review.</p>
    </div>
  </li>
</Steps>

## What's next

<Callout type="tip" title="After the workflow">
  Your project is set up for iterative development. Here is what you can do next:

  **[Deep review](/brewcode/skills/superreview-setup/)** -- generate the project's own quorum review skill, then invoke the generated `/superreview` whenever you need it:
  ```bash
  /brewcode:superreview-setup status
  ```

  **[Extract rules](/brewcode/skills/rules/)** -- convert knowledge into project-wide coding rules. This skill takes a free-form instruction, so say what you want:
  ```bash
  /brewcode:rules "derive rules from .claude/convention/ and the last 200 commits, one file per domain, no duplicates of CLAUDE.md"
  ```

  **[Prompt optimization](/brewtools/skills/text-optimize/)** -- reduce tokens in prompts and agents:
  ```bash
  /brewtools:text-optimize .claude/agents/
  ```
</Callout>
