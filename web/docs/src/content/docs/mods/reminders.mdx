# Reminders

<Badge variant="mod" text="Claude Code 2.1.301+" /> <Badge variant="secondary" text="Works on Team orgs" /> <Badge variant="primary" text="brewmod-reminders" />

Tell Claude what to remember and when. The reminder is a Markdown file in your repo, so it outlives the session. When it fires, a band above the prompt shows it, and you run it with `1` or `**`.

Session cron jobs and `/loop` die with the session, and cloud `/schedule` has no access to your SSH keys, local scripts or VPS. A file-based reminder runs where you work, and only when you say so.

## Quick reference

| Field | Value |
|-------|-------|
| Command | `/remind` (keys run instantly, free text goes to Claude) |
| Picker | `**` in the prompt (prefix is configurable) |
| Kinds | `action`, `note`, `someday` |
| Scopes | project (default), global |
| Settings | `prefix`, `cooldownMinutes`, `notify`, `keepDays` in `/config`; `git` in `.claude/reminders.json` |
| Requires | Claude Code 2.1.301+, `node` on the `PATH` |

## How it works

You say what to remember and when, in plain words. The mod saves a file at once, with no preview and no permission prompt. When the time comes, the reminder is marked as fired and shown in a band above the prompt. You press `1`, type `**1`, or answer Claude's one-line note.

Three kinds cover everything you would put on a sticky note. An action is work for Claude, a note is a message to you, and someday is a thought with no date.

## When to use

| Situation | What you say |
|-----------|--------------|
| Check something after a deploy | `remind me tomorrow at 9 to check the prod logs and show me errors` |
| Remember a task that is yours | `remind me Friday to reply to Ana about pricing` |
| Park an idea | `someday try the new semble release` |
| Need it in every project | `remind me globally on Monday to renew the domain` |
| See what is waiting | `/remind all` or `what fires this week?` |

## Kinds and scopes

| Kind | Mark | What it is for | What happens |
|------|------|----------------|--------------|
| action | ▶ | Work for Claude: "check the prod logs and show me errors" | Claude claims it, runs it when you say so, closes it with a one-line result |
| note | ✎ | A message to yourself: "build the CSV export" | Shown in full, Claude says it was just a reminder, closes it |
| someday | ▶ or ✎ (its kind) | A thought with no date, an action or a note: "someday try the new semble release" | Never fires. Not in the band, toast, alert or Claude's line. Shown only when you ask: the `/remind all` Someday section, `/remind someday`, the `**` picker (after a divider), or "anything to remind me?" |

Say "move it to Friday" and a someday item becomes a normal reminder.

| Scope | Where it lives | Shows in |
|-------|----------------|----------|
| project (default) | `.claude/scheduled/` of the repo | Sessions of that project |
| global | `${CLAUDE_CONFIG_DIR:-~/.claude}/reminders/` | Every project on this machine, per Claude profile; never put in git |

Say "global" or "in every project", or start with `/remind global …`, to pick global.

When you give no time, Claude asks one question, "When should it fire?", with options built from your request, a "No date (someday)" option and Other. The kind or scope joins that dialog only when unclear.

## When it fires

- **Band.** Above the prompt, only fired reminders: `reminders · N fired`, rows like `1: ▶ title  2 h ago` (`✎` for notes, `(global)` suffix), up to 3 rows. With more, the footer adds `+N more`. Nothing fired, no band.
- **Session start.** Open, resume and `/clear` show the band at once.
- **Idle open session.** Within about a minute of the due time: the band, a toast `reminder fired: <title> · ** to pick`, and a desktop alert.
- **Your next prompt.** Claude starts its reply with one line about what fired, then answers. Notes are shown in full and closed.

## Ways to talk to it

| Way | Example | What happens |
|-----|---------|--------------|
| Plain prompt | `remind me tomorrow at 9 to check the prod logs` | Claude creates it. Also answers `anything to remind me?` and `what fires this week?` |
| `/remind` with free text | `/remind check prod tomorrow 9:00` | Handed to Claude: create or answer. Start with `global` or `project` to fix the scope |
| `/remind` with a key | `/remind snooze 1 +1h` | Instant, printed by the mod, no Claude turn |
| `**` picker | `**`, `**1`, `**1 **2` | Pick and run fired reminders |
| Band keys | `1`, `2`, `3` | Fill `**N` in an empty prompt; Enter runs it |

### Pick and run with `**`

- Type `**` to open the picker: fired reminders first, then a `── someday ──` divider and the someday ones. Arrows plus Tab insert `**1`; Enter sends.
- Type `**1` directly. `**1 **2` runs both. `**1 only the last hour` adds your words. `**<id>` works for any reminder, someday included.
- Band keys: a digit `1` to `3` typed into an empty prompt, then a pause of about 0.4 s while a reminder is fired, fills `**1` without sending. Enter runs it; ctrl+u undoes the fill.
- `/remind run <N|id>` does the same; so does saying "run the prod logs one".
- `**bold**` text never expands. Change the prefix with `prefix` in `/config`.
- Two sessions: only one runs a reminder. The other shows `<id> is already running in another session since <time>`.

## Commands

| Command | Result |
|---------|--------|
| `/remind` | Fired reminders, numbered like the band |
| `/remind all [project\|global] [today\|tomorrow\|week\|+Nd\|+Nw\|until YYYY-MM-DD]` | Sections Fired, Waiting, Someday. Fired are always listed; the window filters Waiting |
| `/remind history` | Closed reminders (done, shown notes, cancelled), newest first |
| `/remind someday` | Only the undated ones |
| `/remind run <N\|id> [words]` | Run an action, or show a note and close it |
| `/remind snooze <N\|id> <when>` | `+1h`, `tomorrow 9:00`, `fri 14:00` or `YYYY-MM-DD HH:MM`; gives a someday item a date |
| `/remind edit <N\|id> <change>` | Claude changes text, kind, time or scope and shows `- …` and `+ …` lines |
| `/remind done <N\|id>` | You did it yourself |
| `/remind cancel <N\|id>` | Drop it |
| `/remind reopen <id> [when]` | Bring a closed one back |
| `/remind help` | Help text, and whether the desktop alert is on |
| `/remind [global\|project] <any words>` | Handed to Claude, which adds or answers |

Aliases: `show active|all|done`, `list`. The id is the file name without `.md`; a unique prefix of the slug also matches. Closed reminders are deleted after `keepDays`.

## Settings

| Setting | Where | Default | Effect |
|---------|-------|---------|--------|
| `prefix` | `/config` | `**` | Picker and run token |
| `cooldownMinutes` | `/config` | 60 | Minutes between offers in one session; a newly fired reminder is offered at once |
| `notify` | `/config` | on | Desktop alert when a reminder fires in an open session |
| `keepDays` | `/config` | 30 | Days a closed reminder is kept |
| `git` | `.claude/reminders.json` | `off` | `off`, `commit` or `commit-push` for the item file only |

## Good to know

- **Desktop alert.** Needs a terminal with a notification channel: iTerm2, kitty or ghostty. Inside tmux nothing is sent. `/remind help` ends with the current state.
- **Headless runs.** `claude -p`, CI, the SDK and subagents get no offer; prompts that start with `/` are skipped.
- **Team organizations.** Checked live on a Team seat: band, offer through the bundled command hook, `/remind` hand-off and the mod tools.
- **Worktrees and clones.** Claims and status are per checkout. A tracked item marked done in one checkout shows pending in another until the change is pulled.
- **Git is your call.** The mod never runs git; with `commit` or `commit-push` it tells Claude to commit, and push, only that item file. `.gitignore` is untouched.
- **Nothing runs unasked.** A fired reminder is offered, never started on its own.

<Spoiler title="Technical details" id="technical-details" meta="item files, claims, tools, hooks">

**Item file.** `<YYYYMMDD-HHMM>_<slug>.md` (the prefix is the due time in UTC) or `someday_<slug>.md`. Header lines at the top, up to the first blank line (optional `---` fences): `due: 2026-10-22T08:00:00Z` (UTC `Z`, or `none`), `status: pending|done|cancelled`, `kind: action|note` (missing means action), `done:` or `cancelled:` with a UTC time, optional `created:` and `result:`. The body is the text Claude runs or shows. A `README.md` in the folder is skipped. A time without `Z` is listed as unreadable with the hint to add `Z`. If the mod tools are unavailable, edit the header by hand: `status: done` plus `done: <UTC>`.

**Claims.** Starting an action writes `.claims/<id>.json` in its folder (the folder carries its own `.gitignore` with `*`), so a second open session cannot run it too. A claim from a crashed session expires after 6 h. Claude finishes with `update_reminder done` and a result, which sets `status: done`, `done:` and `result:`.

**Tools Claude uses.** `list_reminders` (`scope`, `state` active, all, someday or done, `from`, `to`), `add_reminder` (`scope`, `when` or `someday`, `text`, `slug`, `kind`, `tz`; saves at once) and `update_reminder` (`action` start, done, snooze, cancel, edit or reopen, plus `until`, `result`, `text`, `kind`, `when`, `scope`, `from_scope`).

**Migrating a hand-written hook.** Items from a custom SessionStart hook (for example `due-checks.sh` with `.claude/scheduled/*.md`) parse unchanged. Remove the hook block from `.claude/settings.json` or `.claude/settings.local.json` and the script; while it is still registered, the offer reminds you to do so.

**State.** Session and offered marks live under the plugin root (`.state/`, pruned after 7 days). An update installs a new version directory, so a fired reminder can be offered once more.

**How it works.** A bundled command hook, `hooks/remind.mjs`, runs on `UserPromptSubmit` and on `SessionStart` with the `compact` matcher, so the offer reaches Claude on Team organizations, where a module's own `classic.*` hooks are bypassed. The module draws the band, runs the tick, the picker and the `/remind` command, and registers the tools above. Every path fails open.

</Spoiler>
