## Use it

| You type | You get |
|----------|---------|
| `++r check the diff` | The review block is added as hidden context. The token stays in your prompt |
| `++` | A typeahead of names. `Tab` inserts the token. A band above the prompt previews the blocks |
| `/placeholders` | The list of placeholders with their layers, plus how to add one |

## Built-in placeholders

| Typed | When | Adds |
|-------|------|------|
| `++m` | always | Manager mode: delegate, never code in the main context |
| `++a` | always | Architecture first: experts design before implementing |
| `++r` | always | Two-phase review, then double-check each finding |
| `++rr` | always | Anti-regression review on three axes |
| `+++` | plan mode | Anti-drift cron plan that keeps work on the goal |

`++rr` beats `++r` when both appear. Brewtools v6.8.0+ no longer ships these codewords: this mod is their only provider.

## Add your own

Run `/placeholders` followed by what you want, in plain words:

```text
/placeholders a ++ship placeholder: release checklist, run tests, update RELEASE-NOTES.md, show me the diff
```

Claude lists the existing placeholders, takes your text as written or drafts it, then asks once: **Save as drafted (Recommended)** or **Change it**. It saves to `.claude/placeholders/` in the project, or globally when you ask, and Claude Code shows no permission prompt for the write. Removal works the same way: **Remove it (Recommended)** or **Keep it**. Only your own layers change, never plugin defaults.

Then type `++ship fix the flaky login test`. The saved body is added as hidden context, and the token stays in your prompt:

```text
Before tagging: run the full test suite, update RELEASE-NOTES.md, then show me the diff.
```

The dialog is verified on 2.1.300; builds without the mod tool API print `needs Claude Code 2.1.300+ for the dialog` and keep the status view. Prefer files? See [Definition files](#definition-files).

## Commands

| Command | What it does |
|---------|--------------|
| `/placeholders`, `status`, `help`, `list` | Shows `<N> placeholders: type ++name in any prompt`, one row per placeholder with layer and description, then `add or change: /placeholders <what you want>` |
| `/placeholders <anything else>` | Starts the model-run dialog above |

Config: `/config` has one option, `prefix` (default `++`, 2-8 ASCII punctuation characters).

## Prompt box

| Feature | Behavior |
|---------|----------|
| Highlight | A known token is underlined. An unknown prefixed word takes the warning colour |
| Typeahead | After the prefix, matching names with descriptions. `Tab` inserts the token |
| Band | One row per distinct token. 1-2 tokens show 3 lines of text at once. With 3+ tokens, press the `Show text  ctrl+x · tab · enter` button: `ctrl+x` (chord, 3 s), `Tab` to focus, `Enter` to toggle without sending, `Esc` back to the prompt |
| Unknown token | A toast such as `unknown ++q` on submit. The prompt is sent unchanged |

Terminal UI only. The band foot reads `add or change: /placeholders`.

<Spoiler id="definition-files" title="Definition files and layers">

One Markdown file per placeholder. The file name is the placeholder name. Front matter is optional, and a file inherits unset keys from the placeholder it overrides.

| Key | Values | Default | Effect |
|-----|--------|---------|--------|
| `name` | 1-32 letters, digits or `_`, or ASCII punctuation | file name | Token name, case-insensitive |
| `description` | text | none | Shown in the typeahead and band |
| `insert` | `context`, `inline` | `context` | `context` adds hidden context and keeps the token. `inline` replaces the token |
| `when` | `always`, `plan`, `not-plan` | `always` | Applies only in that permission mode |
| `order` | integer | `100` | Blocks join from the lowest `order` up |
| `group` | text | none | Placeholders in one group exclude each other |
| `priority` | integer | `0` | In a group, the highest wins |
| `header` | text | none | First line of the block. `{token}` becomes the prefix plus name |
| `legacy` | text | none | Name of the brewtools override file it reads |

- **Body.** With fenced blocks, only the fenced text counts. Otherwise the trimmed text after the front matter.
- **Empty body.** Suppresses the token. Keys are inherited from the layer below, the body is not.
- **Plan variant.** `<name>.plan.md` wins in plan mode.
- **Cap.** Blocks are sorted by `order`, joined and cut at 9000 characters.

The highest layer wins, file by file:

| Layer | Location |
|-------|----------|
| Project | `<launch dir>/.claude/placeholders/<name>.md` |
| Project, brewtools override | `<launch dir>/.claude/brewtools/manager/prompts/<legacy>.md` |
| Global | `<config>/placeholders/<name>.md` |
| Global, brewtools override | `<config>/manager/prompts/<legacy>.md` |
| Plugin | `placeholders/` inside the mod |

`<config>` is `CLAUDE_CONFIG_DIR`, or `~/.claude`. Project layers come from the launch directory, not the git root.

</Spoiler>

<Spoiler title="With brewtools">

- **Update brewtools with the mod.** brewtools 6.7.x plus this mod injects each block twice.
- **Overrides carry over.** Existing files under `.claude/brewtools/manager/prompts/` and `<config>/manager/prompts/` keep working.
- **Silence a token.** Give your override an empty body.
- History: [Codewords (moved to mod)](/brewtools/prompt-injection/).

</Spoiler>

<Spoiler id="technical-details" title="Technical details">

**Team organizations.** Claude Code's builtin security layer bypasses a mod's `classic.*` hooks there. A bundled command hook, `hooks/inject.mjs`, adds the blocks instead. Verified on a Team-org and a Max profile. Enterprise was not run.

- **Load.** Unreadable or invalid definition files are skipped, with a toast and a line in the status view.
- **Match.** A name must stand alone: `++rr` is not `++r`.
- **Inject.** The module expands only inline placeholders and names unknown tokens in a toast. The command hook builds the context blocks, picks plan variants from the permission mode and skips subagent deliveries.
- **Fail open.** Any error returns an empty result, so a fault never blocks a prompt.

The hook records the permission mode in `.state/mode-<session_id>.json` in the plugin root. The band reads it for the plan label, which updates one turn late after `Shift+Tab`.

<Spoiler id="verified" title="Verified" meta="Claude Code 2.1.300">

Live runs use `claude -p`, one turn per case, brewtools disabled. Injections are the `hook_additional_context` rows of the session transcript.

| Check | Result |
|-------|--------|
| `node tests/inject-parity.mjs`: frozen texts, layers, state file, fail-open | 164 checks pass: 98 golden vectors, 34 layer fixtures |
| Team-org and Max profiles, `--plugin-dir` and marketplace copies, Sonnet: `++r` | 1 block, 571 characters |
| Team-org, Sonnet: plan-mode `++m` | 1 block, the plan variant |
| `tests/live/ab.sh`, both profiles, Haiku, 8 cases | PASS: blocks byte-equal to the golden |
| Custom prefix `@@`, Max, Sonnet: `@@r ++r` | Only the `@@r` block |
| Unknown `++q`, Haiku (measured on an earlier build) | Toast on submit, prompt unchanged, no block |
| `/placeholders` dialog, terminal UI, 2.1.300 | Status view, save and remove each ask once, file written without a permission prompt |
| Latency, p50: typing per keystroke (mod minus control, drafts of 0 / 4,000 / 19,700 chars) and band repaint after a token keystroke | Typing -2.6 / +6.6 / +2.1 ms, token keystrokes +2.4 / +6.6 / +5.6 ms, noise as large as the deltas. Repaint 19 to 21 ms at p50, 44 to 61 ms at p99 |

Not covered live: the global layer on disk, the 9000-character cap, `insert: inline`, the `+K more placeholders` row, the unknown-token toast on the current build, fullscreen hover and click, the desktop app, VS Code, subagents and other models. Unit tests cover prefix, layers and cap.

</Spoiler>

<Callout type="warning" title="Known limits">
  A token inserted with `Tab` and a recalled history entry show no highlight or band until the next keystroke. Drafts over 20,000 characters get no highlight or band, but expansion on submit still works.
</Callout>
