# memory — sync and shrink persistent knowledge

<Callout type="caution">
**Memory drifts and only ever grows.** Facts duplicate what CLAUDE.md or a rule already says, claims go stale after a refactor, session scratch notes never get cleaned up — and Claude reads all of it on every session start. A sync that only touches the root `CLAUDE.md` misses nested `CLAUDE.md` files, rules, and conventions, and leaves the drift in place.
</Callout>

<Callout type="tip">
**One sweep, non-growth enforced.** `/brewdoc:memory` re-verifies the whole surface against the codebase, deletes before it adds, and every file must end at or below its original line count. `full` extends the same pass to the agent and skill rosters.
</Callout>

## Quick reference

| Field | Value |
|-------|-------|
| Command | `/brewdoc:memory [free-form prompt]` |
| Arguments | `<free-form prompt: emphasis only; empty = sync whole memory surface; 'full' adds agent+skill rosters>` — a prompt sets emphasis, never narrows the sweep; say "full" / "всё" / name agents or skills to add the roster pass |
| Model | opus |
| Invocation | user-only (`disable-model-invocation: true`) — Claude never auto-triggers it |
| Tools | Read, Write, Edit, Glob, Grep, Bash, Task, AskUserQuestion |

## When to use

| Scenario | Command |
|----------|---------|
| Regular hygiene after a batch of sessions | `/brewdoc:memory` |
| Just renamed paths/flags across the repo | `/brewdoc:memory "focus on renamed paths"` |
| Before a release — also clean agents and skills | `/brewdoc:memory "full"` |
| Suspect a memory entry contradicts a rule | `/brewdoc:memory` (CLAUDE.md + rules win, memory gets corrected) |
| Only the agent roster needs a pass, brewcode installed | `/brewcode:agents sync` (standalone, not via memory) |
| Only the skill roster needs a pass, brewcode installed | `/brewcode:skills sync` (standalone, not via memory) |

## Examples

```bash
# Default: sync the whole memory surface, no prompt needed
/brewdoc:memory
```

```bash
# Prompt steers emphasis only — the sweep still covers everything
/brewdoc:memory "focus on the CI facts"
```

```bash
# Full: memory + agent roster + skill roster + cross-layer dedup
/brewdoc:memory "full"
/brewdoc:memory "всё, включая агентов и скиллы"
```

The skill announces its mode before doing anything:

```
Mode: sync (memory) — no prompt -> default sync
Emphasis: none
```

Final report shape:

```markdown
# memory [sync]
## Surface
| Layer | Files | Lines before | Lines after | Delta |
| memory | 4 | 210 | 128 | -82 |
| CLAUDE.md (root) | 1 | 180 | 165 | -15 |
| CLAUDE.md (nested) | 3 | 96 | 71 | -25 |
| rules | 6 | 240 | 178 | -62 |
| conventions | 1 | 44 | 44 | 0 |
| **Total** | 15 | 770 | 586 | **-184** |
```

## Flow

<Steps>
  <li>
    <div>
      <strong>Input gate</strong>
      <p>The whole prompt is read as free-form emphasis, not a keyword grammar. Empty or any ordinary prompt selects mode <code>sync</code>. Only "full" / "всё" / naming agents or skills selects mode <code>full</code>. A prompt never shrinks the surface, it only steers which facts get scrutinized first.</p>
    </div>
  </li>
  <li>
    <div>
      <strong>Build the surface</strong>
      <p>Read-only discovery of the whole knowledge surface: memory files (<code>$MEMORY_DIR</code> from <code>autoMemoryDirectory</code>, else the legacy <code>&#126;/.claude/projects/&lt;hash&gt;/memory/</code> path), root and <code>.claude/CLAUDE.md</code>, every nested <code>CLAUDE.md</code> at any depth, <code>&#126;/.claude/CLAUDE.md</code> as reference, project and global <code>rules/&#42;.md</code>, and conventions (<code>CONVENTIONS.md</code>, <code>CONTRIBUTING.md</code>, <code>AGENTS.md</code>, <code>docs/&#42;&#42;/convention&#42;.md</code>, <code>@path</code> imports). A run that only touches the root <code>CLAUDE.md</code> is treated as incomplete.</p>
    </div>
  </li>
  <li>
    <div>
      <strong>Verdicts per entry</strong>
      <p>Every fact gets one of eight verdicts: DUPLICATE, OBVIOUS, STALE, OLD, EPHEMERAL, DRIFT, MISPLACED, MISSING. Order of operations is DELETE first, then COMPRESS, then ADD last — never add before cutting. MISPLACED verdicts are queued, not applied here — they move in the cross-file pass below.</p>
    </div>
  </li>
  <li>
    <div>
      <strong>Fan-out, longest file first</strong>
      <p>One subagent per file, parallel batches of up to 8, longest file first. Add gate and line-budget rules: see Internals below.</p>
    </div>
  </li>
  <li>
    <div>
      <strong>Cross-file pass</strong>
      <p>The orchestrator re-reads the changed files: kills facts that now live in two layers, applies queued MISPLACED moves, deletes orphaned memory files after asking, and fixes broken path references left behind by the moves.</p>
    </div>
  </li>
  <li>
    <div>
      <strong>Full mode adds the rosters</strong>
      <p>When mode is <code>full</code>, the same directive and verdicts run again over the agent roster (<code>.claude/agents/&#42;.md</code>, <code>&#42;/agents/&#42;.md</code>) and skill roster (<code>.claude/skills/&#42;/SKILL.md</code>, <code>&#42;/skills/&#42;/SKILL.md</code> plus their <code>references/&#42;.md</code>) — via <code>brewcode:agent-creator</code> / <code>brewcode:skill-creator</code> when brewcode is installed, general-purpose subagents otherwise. A cross-layer dedup pass then keeps duplicated facts in the rule (rules auto-load; artifacts pay the token cost again on every use). This is a separate pass, not a call to <code>/brewcode:agents</code> or <code>/brewcode:skills</code> — both are user-only and brewcode may not even be installed.</p>
    </div>
  </li>
  <li>
    <div>
      <strong>Confirm and report</strong>
      <p>One <code>AskUserQuestion</code> shows total delta, the top-5 longest files before/after, counts per verdict, and every proposed addition with its source — options are Apply all / Apply deletions and compression only / Review each / Cancel. The report then lists the surface table per layer, longest files, deleted entries, stale facts corrected, moves, additions, skipped files, and next steps. Total delta must be <code>&lt;= 0</code>, or justified per line if it is not.</p>
    </div>
  </li>
</Steps>

<details>
<summary>Internals</summary>

**Non-growth is the prime directive** — every file ends at or below its original line count, total delta at or below zero. Longest files are ranked first and compressed hardest.

**Add gate** — a fact enters only if ALL of: non-obvious for a competent model, domain-specific to this project, verified against a real source, and its absence would cost a real failure. One line, with its source.

Banned additions: "write good code", "use clean architecture", "follow SOLID", "add tests", "handle errors", any restatement of a tool's own docs. Wanted instead: domain invariants, environment quirks, mistakes actually hit and their cause.

**Authority** — CLAUDE.md and rules win over memory on conflict. A nested `CLAUDE.md` wins over the root one for its own subtree.

**Mechanics** — one subagent per file, `Edit` only, applied bottom-up by descending line number to preserve line numbers across a multi-edit run. Edits never use `Write` on an existing file.

**Delegation** — every subagent spawn carries GOAL / ROLE / SCOPE / CONTEXT / CONSUMER / DONE; one subagent = one bounded unit, batches spawned in a single message.

**No `context: fork`** — the skill runs in the main conversation because it needs the session's history and spawns `Task` subagents from there.

**Files**

| File | Purpose |
|------|---------|
| `SKILL.md` | Input gate, mode selection, dispatch |
| `references/mode-sync.md` | Steps S0-S5: surface discovery, verdicts, fan-out, report |
| `references/mode-sync-full.md` | Steps F0-F4: sync + agent/skill rosters + cross-layer dedup |
| `references/memory-guide.md` | Where-does-it-belong decision tree, compression patterns, obvious-vs-domain table |

</details>
