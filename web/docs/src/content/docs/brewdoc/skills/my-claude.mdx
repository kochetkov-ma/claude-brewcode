# my-claude: document your setup

<Badge variant="primary" text="opus" /> <Badge variant="secondary" text="user-invoked" />

Maps your Claude Code setup into one shareable Markdown doc: the local config and project `.claude` (internal), the official architecture (external), or a cited answer from live sources (research). An independent agent re-checks every path and count before the run ends.

## Quick reference

| Field | Value |
|-------|-------|
| Command | `/brewdoc:my-claude` |
| Arguments | `[prompt] [ext [context]]` \| `[r <query>]`; no args = internal installation docs |
| Model | opus |

## Modes

| Argument | Mode | What it does | Output (in `.claude/brewdoc/my-claude/`) |
|----------|------|--------------|------|
| *(none)*, or no keyword match | INTERNAL (default) | Rules, agents, skills, memories of the config dir and the project | `YYYYMMDD_my-claude-internal.md` |
| `ext` or `external` | EXTERNAL | Official docs, local hook analysis, recent releases | `YYYYMMDD_my-claude-external.md` |
| `ext context` | EXTERNAL, context-schema | `additionalContext`, `updatedInput`, `decision` | `external/YYYYMMDD_context-schema.md` |
| `r <query>` or `research <query>` | RESEARCH | GitHub, Reddit, forums, marketplaces, with citations | `YYYYMMDD_research-{slug}.md` |

## When to use

- **Onboarding:** hand a new teammate a complete map of your setup.
- **Audit before a release:** snapshot current skills, agents, hooks, and rules.
- **Hook development:** run `ext context` for a fresh reference on which channels work for which events.
- **Custom investigation:** research any topic across live sources.

## Example

```bash
/brewdoc:my-claude                      # internal: your local setup
/brewdoc:my-claude ext context          # context injection schema
/brewdoc:my-claude r plugin hooks additionalContext regression
```

## Flow

<Steps>
  <li><div><strong>Detect mode</strong><p>Picks INTERNAL, EXTERNAL, or RESEARCH and loads its reference file.</p></div></li>
  <li><div><strong>Parallel discovery</strong><p>Internal spawns 3 `Explore` agents (global config, project config, memory); external and research spawn `general-purpose` agents per source group. Each spawn gets one bounded unit and a six-field brief; research runs 2 to 5 groups. Contract: [Delegation](/brewcode/skills/#delegation).</p></div></li>
  <li><div><strong>Write and validate</strong><p>Merges findings into one doc, writes it under `.claude/brewdoc/my-claude/`, then an independent agent checks paths, counts, and sources.</p></div></li>
  <li><div><strong>INDEX entry</strong><p>Appends a record to `.claude/brewdoc/INDEX.jsonl`; asks to bump or add when the mode already has one.</p></div></li>
</Steps>

<Spoiler id="technical-details" title="Technical details">

**Mode selection.** The argument is one free-form prompt (RU or EN). An explicit prefix (`ext`, `external`, `r `, `research `) wins; otherwise the most distinct keyword picks the mode, a tie triggers one question, no match falls back to Internal. The prefix needs a trailing space: `rsome query` is not research mode.

**Internal config path.** Internal mode reads the active config directory (`CLAUDE_CONFIG_DIR`, default `~/.claude`) and the project `.claude`.

**Versus `/team-onboarding`.** The built-in `/team-onboarding` (Claude Code 2.1.101+) covers a quick handoff; use this skill for web research, architecture synthesis, or the persistent INDEX.

**Common mistakes.** Research mode produces documentation, not code; delegate implementation to a project agent. `ext` documents the external architecture; use no arguments for your own setup. Internal mode never copies secret values, only their names.

**Output paths.** Files are listed in the Modes table. Writes under `.claude/` are protected: prompted in `default` and `acceptEdits`, allowed under `bypassPermissions`, never pre-approved by allow rules; headless without bypass fails.

**Validation.** Internal uses `Explore` (read-only path and count check). External and research use `general-purpose`, which re-opens sources with `WebFetch` and `WebSearch`. Fixes land in the written doc.

**Provenance frontmatter.** Every generated doc opens with `doc_type: user`, `version`, `generated_by: "brewdoc:my-claude"`, `last_updated`. `version` comes from the plugin's own `plugin.json`; re-generating refreshes the three stamps and keeps a hand-edited `doc_type` (`llm` or `skip`).

**Internal sources.** `<config>/CLAUDE.md`, `rules/*.md`, `agents/*.md`, `skills/`, project `CLAUDE.md` and `.claude/rules/*.md`, `<config>/projects/*/memory/*.md` (`MEMORY.md` is the index), and `agent-memory/*/`.

**INDEX and legacy migration.** One JSON line per run with `ts`, `mode`, `path`, `title`, `version`. If `~/.claude/brewdoc/INDEX.jsonl` exists and the project INDEX is empty, its entries are merged once (read-only) with a notice; the legacy file is never written.

**Doc structure.** Internal: Global Configuration, Project Configuration, Memory, Summary table. Research: Findings per source group, Sources table (fact, source, reliability), Review Verdict.

</Spoiler>
