# Full Setup

<Badge variant="primary" text="11 setups" /> <Badge variant="secondary" text="27 skills · 9 agents" /> <Badge variant="accent" text="24 of 27 user-only" />

Run `/brewcode:setup-status` first. It lists the setups still to run, with search and conventions before the agents that consume them. Run each one yourself, one per fresh session, and inspect the generated files before committing them.

A `-setup` skill installs a mechanism (agents, hooks, a generated skill, rules, a task board). Use the installed mechanism afterwards; rerun the setup to inspect, refresh, disable or remove it.

```text
/brewcode:setup-status
/brewcode:setup-status brewtools
/brewcode:setup-status convention-setup
```

The first command reports every installed plugin; the others filter by plugin or setup. The dashboard runs no setup; its one optional write is an accepted task-tools settings key.

<Callout type="warning" title="Run setups separately">
  Setups analyse the repository, delegate work and ask for choices. Supply known choices in your prompt and run them one at a time, so later analysis sees the earlier artifacts. All skills use `user-invocable: true`; all but `/brewdoc:publish`, `/brewtools:text-optimize` and `/brewtools:text-human` also set `disable-model-invocation: true`.
</Callout>

## Recommended order

The dashboard groups its run-list into the same seven stages, shown in the Stage column. It omits installed, disabled and unavailable rows and never renumbers the rest; within a stage, partial installs come before stale and missing ones.

| 1 | 1 | [agent-return-setup](/brewtools/skills/agent-return-setup/) | Optional guard that sizes subagent returns; install first so later setups obey it | `/brewtools:agent-return-setup status` |
| 2 | 2 | [semble-setup](/brewcode/skills/semble-setup/) | Code index before other setups analyse the repo; bare call reports status only | `/brewcode:semble-setup install` |
| 3 | 3 | [convention-setup](/brewcode/skills/convention-setup/) | Architecture and testing patterns that agents and review consume | `/brewcode:convention-setup install` |

| 5 | 5 | [agent-router-setup](/brewtools/skills/agent-router-setup/) | Routes spawns to the new agents | `/brewtools:agent-router-setup install` |
| 6 | 5 | [manager-setup](/brewtools/skills/manager-setup/) | Opt-in delegation hard wall | `/brewtools:manager-setup install` |
| 7 | 5 | [agent-deadline-setup](/brewtools/skills/agent-deadline-setup/) | Wall-clock budget per subagent | `/brewtools:agent-deadline-setup install` |

## Shared modes

| Mode | Purpose |
|------|---------|
| `status` | Inspect without changing artifacts |
| `install` | Generate or copy artifacts and wire the mechanism |
| `upgrade` | Refresh from current source, keeping local configuration and disabled state |
| `enable` / `disable` | Resume or pause the mechanism |
| `uninstall` | Remove artifacts or wiring per that setup's ownership boundary |
| `purge` | Remove the additional owned data |

All eleven accept these seven modes. Use explicit modes: most setups pick status when installed and install when absent, but conventions default to install and semble always to status. Convention setup also accepts `full`, `conventions`, `rules` and `paths`; semble adds `reindex`, `optimize` and `resume`.

<Spoiler id="disarm-the-manager-wall" title="Disarm the manager wall">

The installed hard wall can block main-session file and shell tools. Disarm it with:

```text
/brewtools:manager-setup disable
```

The skill runs the installed helper in this form:

```bash
node /abs/path/to/project/.claude/brewtools/manager/manager-state.mjs set hard=false
```

Use the actual project path and call the helper directly: shell operators, expansions and node eval flags invalidate the exemption. If an old installation lacks the helper, have a subagent run `manager-setup upgrade`, then disable the wall.

</Spoiler>

## After setup

Rerun `/brewcode:setup-status` after plugin updates and follow its commands to repair partial installs. A plugin update does not replace files a setup already copied into your project.
