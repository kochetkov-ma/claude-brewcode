# Full Setup

<Badge variant="primary" text="11 setups" /> <Badge variant="secondary" text="27 skills · 10 agents" /> <Badge variant="accent" text="24 of 27 user-only" />

Install the plugins and the two [brewcode mods](/mods/overview/) first ([Installation](/installation/)). Update Claude Code before the mods: they need 2.1.301 or newer (`claude --version`; if it is lower, run `claude update` and restart Claude Code).

Run `/brewcode:setup-status` first. It lists the setups still to run, with search and conventions before the agents that consume them. Run each missing setup yourself, one per fresh session, and inspect the generated files before committing them. Setups that are already installed but stale are the exception: `/brewcode:setup-status upgrade` refreshes them for you (see [After setup](#after-setup)).

A `-setup` skill installs a mechanism (agents, hooks, a generated skill, rules, a task board). Use the installed mechanism afterwards; rerun the setup to inspect, refresh, disable or remove it.

| Command | Does |
|---------|------|
| `/brewcode:setup-status` | Reports the setups of every installed plugin and offers one upgrade for the stale setups |
| `/brewcode:setup-status upgrade` | Upgrades the stale setups with no confirmation question |
| `/brewcode:setup-status brewtools` | Reports one plugin |
| `/brewcode:setup-status convention-setup` | Reports one setup |

The dashboard never installs a setup: its writes are the upgrades you accept and, if you accept it, a task-tools settings key.

<Callout type="warning" title="Run setups separately">
  Setups analyse the repository, delegate work and ask for choices, so run installs one at a time and supply known choices in your prompt; later analysis then sees the earlier artifacts. Only you start them: see [why Claude does not run skills on its own](/faq/#auto-invoke).
</Callout>

## Recommended order

The dashboard groups its run-list into the same seven stages, shown in the Stage column. It omits installed, disabled and unavailable rows and never renumbers the rest; within a stage, partial installs come before stale and missing ones.

| # | Stage | Skill | Why | Command |
|---|-------|-------|-----|---------|
| 1 | 1 | [agent-return-setup](/brewtools/skills/agent-return-setup/) | Optional guard that sizes subagent returns; install first so later setups obey it | `/brewtools:agent-return-setup status` |
| 2 | 2 | [semble-setup](/brewcode/skills/semble-setup/) | Code index before other setups analyse the repo; bare call reports status only | `/brewcode:semble-setup install` |
| 3 | 3 | [convention-setup](/brewcode/skills/convention-setup/) | Architecture and testing patterns that agents and review consume | `/brewcode:convention-setup install` |
| 4 | 4 | [teams-setup](/brewcode/skills/teams-setup/) | Domain agents and the shared intent-guard | `/brewcode:teams-setup install backend "Kotlin services, Postgres"` |
| 5 | 5 | [agent-router-setup](/brewtools/skills/agent-router-setup/) | Routes spawns to the new agents | `/brewtools:agent-router-setup install` |
| 6 | 5 | [manager-setup](/brewtools/skills/manager-setup/) | Opt-in delegation hard wall | `/brewtools:manager-setup install` |
| 7 | 5 | [agent-deadline-setup](/brewtools/skills/agent-deadline-setup/) | Wall-clock budget per subagent | `/brewtools:agent-deadline-setup install` |
| 8 | 5 | [superreview-setup](/brewcode/skills/superreview-setup/) | Project review skill built on conventions and rules | `/brewcode:superreview-setup install` |
| 9 | 6 | [task-board-setup](/brewtools/skills/task-board-setup/) | Board, methodology, anti-drift; asks for `SPEC_MODE` | `/brewtools:task-board-setup install .` |
| 10 | 7 | [memory-sync-setup](/brewdoc/skills/memory-sync-setup/) | Sync auto-loaded context after agents, rules and tasks exist | `/brewdoc:memory-sync-setup install` |
| 11 | 7 | [docsync-setup](/brewdoc/skills/docsync-setup/) | Track documents for staleness | `/brewdoc:docsync-setup install` |

The [brewcode mods](/mods/overview/) change Claude Code itself. [`brewmod-placeholders`](/mods/placeholders/) expands `++` tokens such as `++r` into instruction blocks; [`brewmod-plan-effort`](/mods/plan-effort/) raises effort while you plan. Not installed yet? After `claude update` (Claude Code 2.1.301 or newer), run `claude plugin install brewmod-placeholders@claude-brewcode` and `claude plugin install brewmod-plan-effort@claude-brewcode`, then restart Claude Code.

<Spoiler id="what-the-eleven-setups-install" title="What the eleven setups install">

| Skill | Main artifacts |
|-------|----------------|
| agent-return-setup | Three hook files, `.claude/agent-return.json` |
| semble-setup | User-scope `semble_code` MCP, hooks on six events, `.claude/rules/semble-first.md`, `.claude/semble/`, `.sembleignore`, CLAUDE.md block |
| convention-setup | `.claude/convention/{reference-patterns,testing-conventions,project-architecture}.md`, `.claude/rules/convention.md` |
| teams-setup | Team manifests, trace files, project agents, intent-guard |
| agent-router-setup | `.claude/hooks/agent-router.mjs`, `.claude/brewtools/agent-router.json` |
| manager-setup | Hard-wall guard, state and disarm helper in `.claude/brewtools/manager/` |
| agent-deadline-setup | Deadline hooks, `.claude/agent-deadline.json` |
| superreview-setup | Project `/superreview` skill, references, template baseline |
| task-board-setup | Board tree, task-tracker, task-board skill, tasks rule, PROGRESS, METHODOLOGY, ANTI-DRIFT, task-graph; task-spec only with `SPEC_MODE=on` |
| memory-sync-setup | Project `/memory-sync` skill and references |
| docsync-setup | Three staleness hooks, `.claude/docsync/` |

Agent-return and agent-deadline also accept global scope under `~/.claude/`. Manager installs only the hard wall; the `++m`/`++a`/`++r`/`++rr`/`+++` codewords come from the [brewmod-placeholders](/mods/placeholders/) mod (Claude Code 2.1.301+, see [mods overview](/mods/overview/)).

</Spoiler>

## Shared modes

| Mode | Purpose |
|------|---------|
| `status` | Inspect without changing artifacts |
| `install` | Generate or copy artifacts and wire the mechanism |
| `upgrade` | Refresh from current source, keeping local configuration and disabled state |
| `enable` / `disable` | Resume or pause the mechanism |
| `uninstall` | Remove artifacts or wiring per that setup's ownership boundary |
| `purge` | Remove the additional owned data |

All eleven accept these seven modes. A bare call picks its own default: semble, manager, agent-deadline, agent-return and agent-router run `status`; convention runs `install`; teams, superreview, task-board, memory-sync and docsync run `status` when installed and `install` when absent. Use explicit modes. Convention setup also accepts `full`, `conventions`, `rules` and `paths`; semble adds `reindex`, `optimize` and `resume`.

`--unattended` is a flag, not a mode, and only `upgrade` acts on it; `/brewcode:setup-status upgrade` passes it for you ([the unattended flag](/brewcode/skills/setup-status/#the-unattended-flag)).

<Spoiler id="disarm-the-manager-wall" title="Disarm the manager wall">

The installed hard wall can block main-session file and shell tools. Disarm it with:

```text
/brewtools:manager-setup disable
```

The skill runs the installed helper in this form:

```bash
node /abs/path/to/project/.claude/brewtools/manager/manager-state.mjs set hard=false
```

Use the actual project path and call the helper directly: shell operators, expansions and node eval flags invalidate the exemption. If an old installation lacks the helper, have a subagent run `manager-setup upgrade`, then disable the wall.

</Spoiler>

## After setup

After a plugin update, run `/reload-plugins`, then `/brewcode:setup-status upgrade` in each project: a plugin update does not replace files a setup already copied into your project. What the upgrade leaves on your list, with a reason each: [what the upgrade leaves to you](/brewcode/skills/setup-status/#what-the-upgrade-leaves-to-you).
