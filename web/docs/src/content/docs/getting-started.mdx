# Introduction

<Callout type="note" title="Looking for ++m, ++r or +++?">
  The codewords `++m`, `++a`, `++r`, `++rr` and `+++` come with the [Prompt placeholders](/mods/placeholders/) mod. Install it once and they work in every prompt, next to placeholders you write yourself.
</Callout>

<Callout type="warning" title="Update Claude Code first">
  The mods need Claude Code 2.1.301 or newer. Check with `claude --version`; if it is lower, run `claude update` and restart Claude Code (`exit`, then `claude`).
</Callout>

```bash
claude plugin marketplace add https://github.com/kochetkov-ma/claude-brewcode && claude plugin install brewmod-placeholders@claude-brewcode
```

Then run `/reload-plugins`.

**Brewcode** is a plugin suite for Claude Code: project conventions and rules, domain agent teams, multi-agent quorum review, semantic code search, and tooling to build your own skills, agents and hooks. Recipes (skills) define what to brew, brewers (agents) do the work, and a few hooks handle session start and post-compact recall. Two [brewcode mods](/mods/overview/) from the same marketplace extend Claude Code itself; they are separate plugins, not counted among the four below.

Every skill except `/brewdoc:publish`, `/brewtools:text-optimize` and `/brewtools:text-human` runs only when you type `/plugin:skill`; see the [FAQ](/faq/#auto-invoke) for why.

<Callout type="tip" title="Start with the project foundation">
  Run setup-status first. Set up semantic search, run convention-setup before teams-setup, configure the agent consumers, then install the task board and finish with documentation sync. Follow the [Full Setup](/full-setup/) run list, one setup per session.
</Callout>

## Install

The prompt checks that Claude Code is 2.1.301 or newer, then adds the marketplace and installs the two mods ([placeholders](/mods/placeholders/) first) and the four plugins.

<InstallPrompt plugin="all" mode="install" />

Full instructions: [Installation](/installation/). Upgrading: [`/brewtools:plugin-update`](/brewtools/skills/plugin-update/).

## Four plugins, one suite

| Plugin | Purpose | Skills | Agents | Hooks |
|--------|---------|--------|--------|-------|
| [**brewcode**](/brewcode/overview/) | Conventions and rules, agent teams, semantic search, quorum review, skill/agent/hook/mod creation | 9 | 6 | 2 |
| [**brewtools**](/brewtools/overview/) | Text utilities, secrets scanning, SSH, deploy, manager mode, the opt-in hook layer | 13 | 3 | 1 |
| [**brewui**](/brewui/overview/) | UI / visual / creative tools (placeholder, empty) | 0 | 0 | — |
| [**brewdoc**](/brewdoc/overview/) | Doc-staleness tracking, memory sync, setup docs, PDF, publishing | 5 | 0 | — |

All four install from a single marketplace and load with every Claude Code session. The suite has three registered plugin hooks; project hooks installed by a `-setup` skill are separate. **Naming rule:** a skill ending in `-setup` installs a mechanism you use afterwards; recurring tools keep bare names.

## What makes it different

<CardGrid>
  <Card title="Task board and methodology" icon="document" href="/brewtools/skills/task-board-setup/">
    Domain methodology, per-task work/review/test plans and a task graph. Active top-level tasks get hourly anti-drift timers unless you override them; specs are optional.
  </Card>
  <Card title="Project code review" icon="search" href="/brewcode/skills/superreview-setup/">
    A generated `/superreview` skill. The default runs your build, lint and test gates plus an intent check; a depth word such as `deep` adds domain experts, scope checks and a validator that re-checks every finding.
  </Card>
  <Card title="Convention setup" icon="book" href="/brewcode/skills/convention-setup/">
    Etalon classes and patterns become convention docs, then rules in `.claude/rules/`.
  </Card>
  <Card title="One setup dashboard" icon="clipboard" href="/brewcode/skills/setup-status/">
    `/brewcode:setup-status` shows which of the 11 setups are installed, stale, disabled, partial or missing, with the exact command for each.
  </Card>
</CardGrid>
