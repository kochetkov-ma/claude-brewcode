# skills <Badge variant="secondary" text="opus" />

<Callout type="tip" title="Prompt-driven">Give a free-form prompt; the skill auto-selects a mode and tells you why. Status is the default — a list only on explicit request.</Callout>

## Quick reference

| Field | Value |
|-------|-------|
| Command | `/brewcode:skills` |
| Input | free-form prompt, mode keyword, or empty |
| Specialist | `brewcode:skill-creator` agent |
| List source | `list-skills.sh` — global, project and every installed plugin |
| Description budget | `<= 120` chars, single line |
| Model | opus |

## When to use

- **Check skill health** — run with no args to open the menu, then pick Status (skills), the recommended default, for a health view across global, project, and plugins
- **Fix a non-triggering skill** — `/brewcode:skills improve commit` re-optimizes activation phrases and description
- **Create from a prompt** — `/brewcode:skills create a semantic code search skill` researches and scaffolds a complete skill
- **Batch improve a folder** — `/brewcode:skills improve ~/.claude/skills/` processes every SKILL.md in parallel
- **Explicit listing** — `/brewcode:skills list` when you need a raw table, not a status summary
- **Refresh stale skill knowledge** — `/brewcode:skills sync` (or `синк`) re-verifies claims in every SKILL.md against the real repo, deletes dead lines, never grows a file

## Examples

```bash
/brewcode:skills
/brewcode:skills status
/brewcode:skills create a semantic code search skill
/brewcode:skills improve commit
/brewcode:skills list
/brewcode:skills sync
/brewcode:skills синк по последнему коммиту
```

## How it works

<Steps>
  <li><div><strong>Input gate</strong><p>The whole argument is treated as ONE free-form sentence — no keyword grammar, no argument parser. A non-empty prompt goes to mode selection; no input triggers the no-prompt menu.</p></div></li>
  <li><div><strong>Auto-mode select</strong><p>Announces `Mode: &lt;mode&gt; (skills) — chosen because &lt;evidence&gt;` so you always know which branch executed and why the classifier picked it.</p></div></li>
  <li><div><strong>No-prompt menu</strong><p>When invoked with no argument, presents a single AskUserQuestion with options (in order): Status (skills) — recommended, Status (all: agents+rules+skills), Create, Improve, Review, Sync skills (memory sync), List (plain), Cancel.</p></div></li>
  <li><div><strong>Dispatch</strong><p>Routes to the appropriate handler: `list-skills.sh` for list mode, `brewcode:skill-creator` agent for create/improve, parallel agents for batch, `references/mode-sync.md` for sync. Review mode spawns a single reviewer — the project's agent from `.claude/agents/`, else `general-purpose` — two-phase: review, then double-check findings, then report. After create/improve returns, the coordinator re-runs `mode-sync.md` itself, scoped to only the file just written — no second `skill-creator` spawn — and applies every verdict directly with targeted edits.</p></div></li>
  <li><div><strong>Real status</strong><p>Four blocks, never a flat list: inventory by scope (plugin / project / global — counts, names, load path), state (enabled or disabled via the <code>_SKILL.md</code> toggle marker, model), overlaps and conflicts (same name shadowed across scopes, duplicate triggers or descriptions), and health flags (missing README or frontmatter, weak description triggers).</p></div></li>
  <li><div><strong>Final output</strong><p>Structured report: mode executed, skills affected, findings, paths written or changed, and suggested next invocation if follow-up is warranted.</p></div></li>
</Steps>

## Modes

| Mode | Trigger | Source / agent |
|------|---------|----------------|
| status (default) | any "show me" / "статус" / health intent | inline scan, no external script |
| list | explicit "list" / "список" / "перечисли" only | `list-skills.sh` — self-locating, so plugin skills are found in both the dev checkout and the installed cache |
| create | "create" / "создай" / "new" / "добавь" / "scaffold" | `brewcode:skill-creator` |
| improve | "improve" / "улучши" / "refactor" / "fix", or a bare existing name or path | `brewcode:skill-creator` |
| review | "review" / "ревью" / "validate" / "проверь корректность" | single reviewer: project's `.claude/agents/`, else `general-purpose` — two-phase (review, double-check) |
| sync | `sync`, `синк`, `memory sync`, `актуализируй`, `обнови знания`, `приведи в соответствие с кодом` | `references/mode-sync.md` |
| batch | plural form, "все" / "all", or multiple names or paths | parallel `brewcode:skill-creator` |

## Delegation

<Callout type="caution" title="Why the rule exists">
  A big task handed to one agent = an agent gone for an hour: you cannot observe it, cannot correct it, and it usually drifts off-target.
</Callout>

One subagent = **ONE bounded unit** — here, ONE skill directory: roughly 5 files, roughly 10 steps. A folder target is never one task; it becomes N spawns fired in **ONE message**, one `skill-creator` per `SKILL.md` found.

Every spawn prompt carries six fields. A bare one-line task is never enough:

| Field | Content |
|-------|---------|
| GOAL | the overall task and why it exists — the point beyond the file edit |
| ROLE | what this agent owns; what it must NOT touch |
| SCOPE | exact paths/commands in bounds + explicit out-of-bounds |
| CONTEXT | what is already done, by whom, what runs in parallel — trimmed to what THIS agent needs |
| CONSUMER | who or what uses the result next, and the shape it must fit |
| DONE | acceptance criteria + the exact report shape you want back |

The Phase 2 spawn is the canonical shape: SCOPE is the skill directory and nothing outside it; CONTEXT states that the invocation type was decided in Phase 1 (do not re-ask), hands over the Explore discovery results, and names how many siblings run in parallel; CONSUMER explains that Phase 4 reviewers read the output against `review-prompt.md`, so open questions must stay explicit instead of being guessed away.

<details>
<summary>Create / improve pipeline (advanced)</summary>

Reachable ONLY via create/improve modes.

**User parameters collected via AskUserQuestion:**

- Invocation type: User-only / LLM-auto / Both
- Testing depth: Quick / Standard / Deep
- Review type: Simple / Quorum (available for Standard and Deep only)

**Pipeline phases:**

- Phase 0 Discovery: 2–3 parallel Explore agents scan existing skill patterns, project structure, and (for create) web-research the topic.
- Phase 4 Review: Simple = one reviewer + one verify agent. Quorum = three reviewers in parallel, 2/3 consensus threshold, DoubleCheck pass, Skill Creator fixes verified findings.
- Phase 5 E2E: Deep depth only. Isolated temp project, `claude -p` execution, up to 2 retries per failed scenario.

**Description budget:** `<= 120` chars, single line, trigger keywords included. One number, enforced in both places — the authoring rule in `SKILL.md` and the review checklist in `references/review-prompt.md` — so a skill written to spec passes its own review. The bound is empirical: 16 of the 27 shipped skills sit at or under 120 characters (95-118); the rest run long, up to 410.

**Specialist:** `brewcode:skill-creator` agent.

</details>

<details>
<summary>Sync mode</summary>

Reachable via `sync` / `синк` / `memory sync` / `актуализируй` / `обнови знания` / `приведи в соответствие с кодом`. Owns `references/mode-sync.md` (steps S1-S6) — `/brewcode:agents` reads the same file, so the two rosters never drift apart.

**Scope (S1):**

| Scope | Meaning | Default |
|-------|---------|---------|
| `repo` | whole working tree | yes |
| `session` | this conversation: decisions, corrections, bugs hit | no |
| `commit` | `git show`/`git diff &lt;ref&gt;`, default HEAD | no |

Announced as `Sync scope: &lt;scope&gt; — &lt;evidence&gt; | targets: &lt;N&gt; skills`.

**Non-growth directive:** each file ends &lt;= its original line count, total delta &lt;= 0 (a positive delta needs per-line justification, never buried). Order: DELETE first, FIX, ADD last.

**Auto-dispatch after create/improve:** once a `create` or `improve` completes, the same engine runs again scoped to only the file just written (its `SKILL.md` + `references/`) — ground truth (S3) through verdicts (S5), folded into one row of the Step 6 report. No second `skill-creator` spawn: the coordinator applies every verdict itself with targeted `Edit` calls, since the S4 fan-out step is skipped for this scoped pass. A clean file reports one line: `sync: no drift`.

**Verdicts (S5):**

| Verdict | Action |
|---------|--------|
| STALE | fix to minimal true form |
| DEAD | delete, plus anything that only explained it |
| DUPLICATE | keep the single best location |
| OBVIOUS | delete |
| DRIFT | compress prose to a table row |
| MISSING | add &lt;= 1 line, only if verified against a real source |

**Report (S6):** per-target table (File, Lines before-&gt;after, Fixed, Deleted, Added, Key change) + stale facts corrected + skipped + total delta.

</details>
