# semble-setup — semantic search with isolated content variants

<Badge text="opus" />
<Badge text="mcp" />
<Badge text="human-invoked" />

<Callout type="tip">
**One setup, one shared cache, no content-set eviction.** Semble 0.6.2 keeps code, docs, config, and combined searches as separate variants under the same repository cache. The registered default covers all three, while each tool call can narrow its own search without replacing sibling indexes.
</Callout>

## Quick reference

| Field | Value |
|-------|-------|
| Command | `/brewcode:semble-setup [status\|install\|upgrade\|enable\|disable\|uninstall\|purge\|reindex\|optimize\|resume]` |
| Arguments | a mode keyword, or free text in RU/EN |
| No-arg default | **always `status`** — see the exception note below |
| Model | opus |
| Tools | Read, Bash, AskUserQuestion |
| MCP server | `semble_code`, registered at **user** scope, pin `semble[mcp]==0.6.2` |
| Tool input | required `repo`; optional `content=code\|docs\|config\|all` |

<Callout type="caution" title="The one skill that never defaults to install">
Every other `-setup` skill treats a bare invocation as `status` when installed and `install` when not. `semble-setup` breaks that rule on purpose: `install` runs `brew install uv`, a **machine-level** mutation outside the project. A bare `/brewcode:semble-setup` must never be able to trigger it, so empty input always resolves to read-only `status`. To install, type the verb.
</Callout>

## What it does

`semble-setup` is the lifecycle router for `semble_code` — a semantic repository-search MCP server that gives Claude two tools: `mcp__semble_code__search` (find code by intent) and `mcp__semble_code__find_related` (neighbors of a known location). The skill never edits code itself; it installs the prerequisite, registers the MCP server, wires a project rule and hooks, and migrates project agents so they can call the tools.

It always prints the current state before changing anything. Every mutation goes through a script under `scripts/` — the skill only decides which one to run and reports the result.

Semble has no Homebrew formula of its own. The skill installs `uv` via `brew` (a machine-level step gated by an explicit confirmation) and then runs the pinned `uvx --from 'semble[mcp]==0.6.2' semble --content <SEMBLE_CONTENT_ARGS>` — never a floating version. The registered/default selection is `code docs config`; a tool call may optionally choose `code`, `docs`, `config`, or `all` for that query. `docs` and `config` use narrower siblings, while `all` reuses the registered combined variant. See Corpus below for the coverage boundaries.

## When to use

| Situation | Command |
|-----------|---------|
| First time on a project, nothing wired yet | `/brewcode:semble-setup install` |
| Just reloaded Claude Code after `install` | `/brewcode:semble-setup resume` |
| Check current state, no changes | `/brewcode:semble-setup` (empty input) |
| Something looks off, want a diagnostic | `/brewcode:semble-setup optimize` |
| A newer `semble[mcp]` pin is approved | `/brewcode:semble-setup upgrade` |
| Turn search off without deleting anything | `/brewcode:semble-setup disable` |
| One repo's index looks stale | `/brewcode:semble-setup reindex` |
| Free-text works too, in English or Russian | `/brewcode:semble-setup rebuild the index` |
| Remove the wiring, keep or drop pieces | `/brewcode:semble-setup uninstall` |
| Wipe everything of this project, including its cache entry | `/brewcode:semble-setup purge` |

## Example

```
/brewcode:semble-setup install
```

`install` probes `uv`, asks once before the machine-level `brew install uv`, registers the MCP server, then wires the rule, `.sembleignore`, the `CLAUDE.md` block, the three hooks, permissions and agent migration before stopping at the reload checkpoint. Reload makes the registered MCP tools visible to Claude; the pinned CLI smoke does not require MCP connectivity, but the workflow defers it to `resume`:

```text

scope: user

mcp:      absent @ user  [unknown]
cache:    /Users/me/Library/Caches/semble-code | repo unknown | variant index-code-config-docs | 0 B | absent
guidance: rule absent | CLAUDE.md absent | hooks 0/4 wired | permissions no
agents:   4 total | 2 inherit | 0 patched | 2 need patch | 0 conflict | 0 skipped
state:    phase=absent enabled=null completed=[]

## Actions
changed:   brew install uv, semble_code registered @ user, rule installed, .sembleignore installed, CLAUDE.md block installed, 3 hooks wired, permissions merged, 2 agents patched
unchanged: none
skipped:   none
failed:    none

## Verification
commands: bash scripts/semble-install.sh all --yes --json
commands: bash scripts/semble-mcp.sh add --scope user --yes --json
commands: bash scripts/semble-guidance.sh install --part all --json
commands: bash scripts/semble-agents.sh apply --scope project --yes --json
smoke:    skipped (install mode does not run smoke)
corpus:   code docs config | repo unknown | unknown
uncovered: .json/.json5/.csv/.tsv/.psv (no content type reaches them), .mdx/.txt (absent from _EXTENSION_TO_LANGUAGE) -> use rg

## Current Status
reload required — MCP registered, waiting for a new session

## Next Step
Reload Claude Code (new session), then run: /brewcode:semble-setup resume

```

The `/4` in `guidance:` counts settings registrations, not hook files - three files wire four rows (`SessionStart`, `PostToolUse`, `PostToolUseFailure`, `SubagentStart`), so `3 hooks wired` under Actions and `hooks 0/4 wired` under Before both describe the same install correctly.

After a fresh session exposes the MCP tools to Claude, `resume` re-checks status, runs the pinned CLI smoke against the same shared cache and combined variant, and re-applies the wiring idempotently so any drift self-repairs:

```
/brewcode:semble-setup resume
```

## Technical details

### Modes

| Mode | Effect | Mutates |
|------|--------|---------|
| `status` | full report: prereqs, MCP, cache, guidance, agents, coverage, state — **the default on empty input** | no |
| `install` | install `uv`, register `semble_code` at user scope, wire the rule, `.sembleignore`, `CLAUDE.md`, hooks, permissions and agent migration, checkpoint for reload | yes |
| `upgrade` | compare the recorded pin against `0.6.2`, re-register if different, then re-sync the rule, `.sembleignore`, hooks and permissions, and delete retired hooks — the only path that moves the artifact version stamp. See Version tracking for the rule and `.sembleignore` verdicts | yes |
| `enable` | turn back on: verify, warm, phase -> `ready` | yes |
| `disable` | `enabled=false` — hooks go silent, nothing deleted | yes |
| `uninstall` | four flavours: `integration` / `mcp` / `cli` / `purge` | yes |
| `purge` | everything of this project: this project's cache entry (all its content variants) is removed, the shared cache root stays unless it ends up empty, and the MCP rollback copies (`.claude.json.bak.<epoch>`, `.mcp.json.bak.<epoch>`) that its own removal took are deleted — typed confirmation required | yes |
| `reindex` | extra: stage and verify the combined variant, replace only `index-code-config-docs`, preserve sibling variants, then remove a legacy combined bare `index` only when its metadata matches | yes |
| `optimize` | extra: read-only audit fan-out with concrete recommendations — reads current cache size, staleness and entry count via `semble-cache.sh info --json` (figures vary by machine/repo, no fixed number published) | no |
| `resume` | extra: after reload — smoke query, then an idempotent self-repair re-run of the same wiring, `phase -> ready` | yes |

The first seven rows are the canonical vocabulary shared by every `-setup` skill. `reindex`, `optimize` and `resume` are semble-specific extras with no equivalent elsewhere. `warm` is not a mode: free text such as `warm the cache` routes to `reindex` and takes its no-delete `semble-project.sh warm` branch. `setup`, `update` and `remove` remain accepted free-text synonyms for `install`, `upgrade` and `uninstall`; English and Russian input are both supported.

### Prerequisites

| Package | Required? | If declined or impossible |
|---------|-----------|----------------------------|
| `uv` / `uvx` (`brew install uv`) | required — `install` asks first, stops on decline | manual fallback `curl -LsSf https://astral.sh/uv/install.sh \| sh` is printed, never run |
| `coreutils` (`brew install coreutils` -> `gtimeout`) | optional — offered only when no `timeout`/`gtimeout` binary exists and `brew` does | nothing breaks: `sc_timeout` keeps its pure-bash watchdog, every shell-out stays bounded either way |

`semble-install.sh` takes one of `check \| uv \| coreutils \| semble \| all` — `all` runs them in that order and is what `install` calls.

### What `install` installs

| Surface | Location |
|---------|----------|
| MCP server | `~/.claude.json` `.mcpServers.semble_code`, user scope — `-s user` is mandatory, the CLI default is `local`. A failed `add`/`repair` restores the file it was about to overwrite |
| Command | `uvx --from 'semble[mcp]==0.6.2' semble --content <SEMBLE_CONTENT_ARGS>` (Corpus below has the actual token list) |
| Shared cache root | absolute `SEMBLE_CACHE_LOCATION`: macOS `~/Library/Caches/semble-code` / Linux `${XDG_CACHE_HOME:-$HOME/.cache}/semble-code` |
| Content variants | one hashed repository directory with `index` for code-only and `index-<sorted-content>` for every other exact selection; `docs` and `config` use narrower siblings, while the registered corpus and `all` both use `index-code-config-docs` |
| State | `<repo>/.claude/semble/state.json` — project root resolved by the canonical recipe: `CLAUDE_PROJECT_DIR` -> `git rev-parse --show-toplevel` -> an upward walk for `.git`/`.claude` -> `PWD`. The walk's `.claude` step skips `HOME` and the profile parent (the directory whose `.claude` is the active config dir), in the scripts and in the three hooks; user-scope `add`/`repair`/`checkpoint` write no `state.json` there (`semble-mcp.sh add|repair --no-state` forces this; `checkpoint` exits 3). An explicit `CLAUDE_PROJECT_DIR` or git toplevel is taken as given, even when it is `HOME` |
| Rule | `<repo>/.claude/rules/semble-first.md` |
| Ignore file | `<repo>/.sembleignore` — keeps generated/vendored trees out of the corpus; managed like the rule (user edits reported, never clobbered) and gets an appended, **commented-out** block of measured candidates (duplicate trees, heavy directories) — nothing is excluded until the user uncomments a line. Candidates and `audit` honour `.sembleignore` and `.gitignore` like semble's own walker |
| CLAUDE.md | a marked `<!-- BEGIN brewcode:semble -->` block, refreshed in place (one copy, never appended twice); the matching `<!-- END brewcode:semble -->` closes it. Other tools that rewrite `CLAUDE.md` (`context-slim`, `memory-sync`, `task-board-setup`, `text-optimize`) keep the marked range byte-identical. Unpaired or duplicated markers count as `malformed`: nothing is written and the user fixes the file by hand. Only `uninstall` removes the block |
| Hooks | three files in `.claude/hooks/` — `semble-session.mjs` (SessionStart, no matcher), `semble-stats.mjs` (PostToolUse + PostToolUseFailure, matcher `mcp__semble_code__search\|mcp__semble_code__find_related\|Bash\|Grep\|Glob\|Read`), `semble-subagent.mjs` (SubagentStart, **no matcher key** — matches every agent type) — four `settings.json` registrations total, each `"timeout": 5` (seconds), each with a portable argument `${CLAUDE_PROJECT_DIR}/.claude/hooks/<file>.mjs` so the tracked `settings.json` works in every clone. Status reports `hooks <n>/4 wired` — never 3 files. `semble-explore.mjs`, `semble-reminder.mjs` and `semble-prefetch.mjs` are retired: `install`/`upgrade` deletes the files and their markers and removes their settings rows, reconciling rather than appending. See Retired hooks below |
| Permissions | exactly `mcp__semble_code__search` and `mcp__semble_code__find_related` in `settings.json`, never a wildcard. Status counts `permissions yes` when any layer grants the tools (tracked `settings.json`, `settings.local.json`, the profile's user settings, or a server-wide `mcp__semble_code` / `mcp__semble_code__*` entry); `install` writes only the tools no layer grants and reports `permissions granted by <file> are not copied into <settings.json>` |
| Agents | project `.claude/agents/**/*.md` get the two tool names added to `tools:`; global agents are never touched. `apply` records, per file, exactly which tool names it added; `--revert` strips only those recorded names and leaves any user-authored tool name in the same list untouched — a file with no record declines to revert rather than guessing |

### CLAUDE.md conflict scan

`install` reconciles the root `CLAUDE.md` (`--part claudemd`) right after it installs the `<!-- BEGIN brewcode:semble -->` block. It scans the rest of the file (the skill's own marked block is never a candidate) for lines that assert a competing search doctrine, against a two-tier pattern set:

| Tier | Match | Result |
|------|-------|--------|
| DENY | explicit contradiction - grep/glob called a no-op/removed/unavailable, semble/semantic search called broken/unreliable/disabled, or "never/dont use semble" | line removed |
| FIRST | competing claim - "search via `<tool>`", "always use `<tool>` for all/any/every/code", "`<tool>`-first", "`<tool>` before semble", or "all searches through `<tool>`" | line removed, unless KEEP-exempt |
| KEEP (exempt) | scopes the tool to exact/literal/identifier/regex/path/filename/exhaustive/enumeration/verify/count - the skill's own correct guidance | never touched, not even reported |
| neither | mentions a search tool without matching DENY or FIRST | left untouched, reported `skipped` for manual review |

The KEEP exemption applies only to the FIRST tier — a DENY match is always removed regardless of scoping words in the same line.

The scan reads the root `CLAUDE.md` only and never walks into a nested one, and a search-titled heading that a removal leaves empty is removed along with it.

Finding a contradiction: backs up the whole file (`sc_backup`), strips the offending lines, reports `changed` with the exact line numbers and text removed. `SEMBLE_DRY_RUN=1` prints what it would remove without touching the file. No contradiction found: reports `unchanged`.

<Callout type="caution" title="Built on a hypothesis the data refuted">
The motivating idea was that a contradicting CLAUDE.md line suppresses conversion to semble. A controlled A/B tested it directly: sessions with the contradiction present converted 5/14 = 36%, sessions with it removed converted 4/18 = 22% — the "clean" arm was nominally *worse* (Fisher exact two-sided p = 0.45, n = 32). Removing false statements about the toolchain is still correct on its own merits, but it is not shown to change tool choice — treat this as documentation hygiene, not a conversion fix.
</Callout>

### Retired hooks

Three hook files are retired and no longer ship. `install`, `upgrade` and `uninstall` delete the files and their markers, and the settings merge removes every matching row (any matcher, path or command form).

| Retired hook | Was | Retired in | Why |
|--------------|-----|-----------|-----|
| `semble-explore.mjs` | `SubagentStart`, pinned to `agent_type === 'Explore'` | 5.0.0 | replaced by `semble-subagent.mjs`, which has no matcher key and so matches every agent type |
| `semble-reminder.mjs` | `PreToolUse` on `Bash\|Grep` | 6.5.0 | a same-profile A/B found no gain (below); the hook fired 0 times |
| `semble-prefetch.mjs` | `UserPromptSubmit` | 6.5.0 | same A/B: its candidate files never held the answering file |

Retired markers: `.claude/semble/.reminder-ts`, `.claude/semble/.prefetch-ts` and `.claude/semble/reminder.json`. The `.gitignore` lines for the first two are stripped.

<Callout type="note" title="Why 6.5.0 dropped the advisory pair">
A same-profile A/B ran 36 sessions per run. The pooled semble share was 42% with the 6.4.0 hooks and 42% with the repaired 6.5.0 hooks; the arm with no hooks scored 38% and 54%. That is one repetition per cell, so it gives direction only, not a proof. Reminder and prefetch added nothing measurable, so they were removed rather than tuned again.
</Callout>

Older telemetry logs may still hold `src:"reminder"`, `src:"prefetch"` or `src:"explore"` records. The status reader counts them per channel; nothing writes them any more.

### `.gitignore` behaviour

`install` adds the `.claude/semble/` line to the repository `.gitignore` only when no rule there already ignores `state.json`, `telemetry.jsonl` and `.dir-probe`. A covering rule such as `/.claude/*` is listed under `unchanged` and nothing is written:

```text
gitignore: .claude/semble/ already ignored by <file>:<line>:<pattern> - not appended
```

Only repository `.gitignore` rules count: `core.excludesFile` and `.git/info/exclude` are per-machine, so they never suppress the line, and a negated (`!`) deciding rule never counts as cover. Removal drops the `.claude/semble/` line with its `# brewcode:semble` header and the retired marker lines, whoever wrote them; a covering rule stays.

### Measured delivery

CC 2.1.226, real headless sessions, joined on `tool_use_id` between the hook's own telemetry record and the `hook_additional_context` transcript attachment. Only the surviving channels are listed.

| Finding | Number |
|---------|--------|
| `SubagentStart` delivery | 8/8 with the registration installed, 0/6 with it removed (negative control); 36/36 over 6 agent types in a 525-transcript corpus |

<Callout type="caution" title="SubagentStart is proven to deliver, not to route">
The registration's text reached 8 of 8 subagents when installed and 0 of 6 when removed — a clean negative control that the registration is what puts the text into a subagent's context. It is **not** proven to change tool choice: every spawn prompt in both arms already carried a literal `start with ONE mcp__semble_code__search` instruction, so first-tool semble was 14/14 with and without the hook. The hooks are insurance, not a measured adoption mechanism; never read a conversion percentage as proof.
</Callout>

Parent and subagent contexts are disjoint: the `SubagentStart` context is visible only inside the subagent and is written only to `<session-id>/subagents/agent-<id>.jsonl`, never to the parent transcript.

`semble-status.sh` reports conversion per source (`session`, `subagent`, plus the retired `reminder`, `prefetch` and `explore` slots for old logs), not one pooled denominator, because pooling let 126 `SessionStart` firings drown every other channel. A channel that never fired prints `0/0`: `0/0` is "never delivered", `0/N` is "delivered and ignored", and only the second is evidence about the advice.

### Skipped is not failed, and a partial verdict is honest

A skipped operation exits **RC 3** with `"status":"skipped"` in its JSON — distinct from a real failure (RC 1). `SEMBLE_NO_NETWORK=1`, `SEMBLE_DRY_RUN=1` or a missing `uvx` skip the smoke query, `warm`, `enable` and `reindex`'s staged rebuild the same way: nothing broke, nothing was proven. `resume`/`enable` leave `phase` at `verifying` rather than `ready` on a skipped warm, and `status` reports the gap as `partial - warm and smoke not recorded in state.completed`, naming exactly the missing member(s) of the pair.

The verdict logic itself follows one rule: a guidance section that **errored** always downgrades the overall verdict from `ready` to `partial`, whatever the cause — a missing unit, a crashed probe, a malformed file all count the same, because each leaves the rule, hooks and permissions exactly as unproven. A **null** measurement never downgrades anything — null means the section was not requested (`--section mcp`), and an absent measurement is not a defect. `cache` and `agents` stay lenient by design since each witnesses one optional fact.

### Version tracking

`status` compares the version stamped into the installed artifacts against the plugin running on this machine, folded into the same `guidance:` line:

```text
guidance: rule managed | CLAUDE.md present | hooks 4/4 wired | permissions yes | version X.Y.Z (plugin A.B.C - run /brewcode:semble-setup upgrade)
```

A hook row whose argument is an absolute path (the 6.5.0 shape, valid only on the checkout that wrote it) is `drifted` and drops the project to `partial`; see the ladder below. `upgrade` (and `install`) rewrite those rows in place to the portable form `${CLAUDE_PROJECT_DIR}/.claude/hooks/...`, keep foreign hooks, and a second run is a byte no-op.

Leftover retired hooks (files or settings rows) print `retired:  <names> - stale (remove via upgrade)`, the verdict reason reads `stale (remove via upgrade): <names>`, and a project that is otherwise `ready` drops to `partial` with the same next step. The JSON fields are `.guidance.retired` (files) and `.guidance.retiredWired` (registrations). They are never counted as missing hooks.

The stamp lives in the frontmatter of `.claude/rules/semble-first.md` (`version:`) and on line 2 of each hook file (`// brewcode-meta: version=X.Y.Z generated_by=brewcode:semble-setup`). When the two disagree, the overall verdict drops from `ready` to `partial` and **Next Step** becomes `Run /brewcode:semble-setup upgrade`. Stamping never fabricates a value it cannot resolve — the resolver refuses to write rather than bake in a fake version.

The rule and `.sembleignore` are compared after the stamp is stripped. Identical content is `unchanged`; a metadata-only delta is re-synced as `re-synced <path> (metadata only)`; a byte-pristine copy of any earlier release (v4.5.0 to v6.4.0) is replaced as `upgraded <path> (pristine prior-release copy)` with no `--force` and no backup, and `status` shows it as `stale` (`semble-first rule is a prior-release copy`). Anything else is `user_modified`: skipped, with a diff on stderr, and overwritten only by `--force` after a backup. A hand-edited rule at an old stamp never gets plain `upgrade`; see the ladder below. `uninstall` deletes a pristine prior copy without a backup.

`upgrade`'s idempotence was tightened alongside it: a run with nothing to change now reports `unchanged`, not `changed` — the `.sembleignore` half snapshots itself before and after so a template re-sync followed by the candidates re-append collapses to a net-zero result instead of a false positive on every run. And because the MCP server is registered at **user** scope, a second project on the same machine used to short-circuit on "already registered" and never receive its own `state.json`; every project now gets one, regardless of what an earlier project already wrote.

<Callout type="note">
`unchanged` from `install`/`upgrade` is never a promise of byte-identity with the plugin template — a stale metadata stamp on otherwise identical prose re-syncs and reports itself as `re-synced ... (metadata only)`, and a managed `.sembleignore` legitimately differs from the shipped template the moment `install` appends its measured-candidates block. Read `Actions`, not just the verdict, before assuming nothing moved.
</Callout>

| Only warm/smoke unrecorded, and/or the index variant missing (for example an index-only cache) | `/brewcode:semble-setup resume` - warm builds the variant |
| Hand-edited rule at an old or missing `content_version` (`.guidance.ruleStampStale`; an unstamped edited rule is `partial`, not `ready`) | The skill never edits or merges it. User review: `diff -u .claude/rules/semble-first.md <template>`; to replace it, `/brewcode:semble-setup upgrade --force` typed in the prompt (backs up `semble-first.md.bak.<epoch>` first, `.sembleignore` needs its own approval) |
| Pin moved, retired hooks left, a pristine prior-release copy, agents needing a `tools:` patch, or artifacts at an older `content_version` (rule not hand-edited) | `/brewcode:semble-setup upgrade` |
| Only absolute-path hook rows (the 6.5.0 shape): `.guidance.absoluteCount`, line `portable:  N absolute-path hook entries (break every other clone) - run /brewcode:semble-setup upgrade` | `/brewcode:semble-setup upgrade` - rewrites them in place |
| Any install step missing | `/brewcode:semble-setup install` |

### Reload boundary

A newly registered MCP server is not usable by Claude until a **new Claude Code session** loads its tools. `install` writes the checkpoint and stops there. `/brewcode:semble-setup resume` then runs the pinned CLI smoke — which does not require MCP connectivity — and completes verification in the new session.

### Tool contract

Both `mcp__semble_code__search` and `mcp__semble_code__find_related` require `repo` — an absolute project root or an explicit HTTP(S) Git URL. It is never inferred. Both accept optional `content=code|docs|config|all`; omitting it uses the registered `code docs config` selection. `docs` and `config` select narrower siblings, while `all` resolves to the same three types and `index-code-config-docs` variant as the registered selection. Results carry `file_path`, `start_line`, `end_line`, `score` and optional result `content` — there is no result `line` field. Defaults: `top_k=5`, `max_snippet_lines=10`.

### Corpus and coverage

<Callout type="note">
  The registered/default corpus is the `--content` set named by `SEMBLE_CONTENT_ARGS` (currently `code docs config`) and lives in `index-code-config-docs`. Per-call `code`, `docs`, or `config` chooses its exact narrower variant without replacing another selection; `all` resolves to the same three types and reuses `index-code-config-docs`. `docs` is what includes Markdown; a `code config` selection indexes zero `.md` files. `.html`/`.htm` are in the docs bucket. `.json`/`.json5`/`.csv`/`.tsv`/`.psv` are excluded from every content type, unreachable even with `content=all`; `.mdx`/`.txt` are absent from semble's extension table entirely. `rg` stays the tool for those, and for exact identifiers, regexes, and exhaustive enumeration.
</Callout>

### Honest limits

| Fact | Consequence |
|------|-------------|
| No watcher, no daemon | The index is built inside a tool call and cached; staleness is re-checked per call. Nothing runs in the background. |
| Every shell-out is time-bounded, with or without `coreutils` | `sc_timeout` uses `timeout`/`gtimeout` when a binary is present and a pure-bash watchdog when none is — the report's `timeout.bounded` is always `true`. `coreutils` only upgrades which binary enforces the bound; it is never required and never a reason a run can fail. |
| Cold cache = slow first query | The embedding model download can take up to 600s and fails offline with a cold HuggingFace cache. |
| Exact content selections share one root without sharing an index | Semble 0.6.2 stores exact selections below the repository hash: code-only is `index`; `docs` and `config` use narrower siblings; the registered combined corpus and `all` both use `index-code-config-docs`. |
| `semble clear index` wipes every repository and variant under the shared root | There is no selective rebuild CLI, so `reindex` builds `index-code-config-docs` in a private staging root, proves a real query, and swaps only that live variant. A failed or skipped staged warm leaves every live variant untouched; a failed final swap keeps the staged path for recovery. A pre-0.5.5 combined bare `index` is removed only after its metadata identifies the same `code docs config` corpus and the replacement is live. |
| Windows is unsupported | The skill refuses every mutation on a non-macOS/Linux platform. |
| Config backups (`<file>.bak.<epoch>`) | Written mode `0600`; the newest 3 per file are kept and each pruned one is named on stderr (`pruned backup: <path> (keeping newest 3)`). |
