# Skills

Skills (recipes) are slash commands that define *what* to do. Each skill is described in a `SKILL.md` file
with frontmatter metadata and instructions for agents. Brewcode includes 9 skills covering
the full task lifecycle -- from project analysis to E2E testing.

On top of those there is a **dynamic tenth skill**: it is not shipped with the plugin, it is **generated into every target project** by [`/brewcode:superreview-setup`](/brewcode/skills/superreview-setup/) and invoked there as `/superreview`, tailored to that project's tech stack, agents, rules and tracker. See the [emitted skill page](/brewcode/skills/review/) for details.

## The `-setup` naming rule

<Callout type="tip" title="Read the suffix, know what you get">
A **`-setup`** skill installs a mechanism — agents, hooks, a rule, a generated skill — that you use afterwards **instead of** the skill itself. You run it once, then `upgrade` it when the plugin moves on. Skills with a **bare name** are recurring tools: you run them again and again, and they leave no installed state behind.
</Callout>

Setup skills draw their verbs from one vocabulary, in this order:

`status` · `install` · `upgrade` · `enable` · `disable` · `uninstall` · `purge`

A bare invocation normally means `status` when installed and `install` when absent.
[`semble-setup`](/brewcode/skills/semble-setup/) always defaults to `status`, because installation
reaches outside the project. [`convention-setup`](/brewcode/skills/convention-setup/) defaults to
`install` and checks status before extraction.

All eleven `-setup` skills implement all seven verbs, via one of two mechanisms: a live config flag the reader re-checks on every invocation, or entry-file parking, where the filename discovery keys on is renamed `<name>.disabled` with the body left byte-identical. [`teams-setup`](/brewcode/skills/teams-setup/) uses parking: `enable`/`disable` move each roster member's agent file between `<agent>.md` and `<agent>.md.disabled`. Skill-specific extras come after the canonical set, never in place of it: `reindex`, `optimize` and `resume` on `semble-setup`.

## Delegation — one contract, all nine skills

Every skill here except read-only `setup-status` fans work out to subagents, and all of them follow the same sizing rule.

<Callout type="caution" title="Why the rule exists">
  A big task handed to one agent = an agent gone for an hour: you cannot observe it, cannot correct it, and it usually drifts off-target.
</Callout>

One subagent = **ONE bounded unit**: one deliverable, roughly 5 files, roughly 10 steps. Larger
work splits into independent parallel assignments. Convention setup partitions layer analysis,
E2E partitions scenarios, and teams setup creates agents one file per spawn.

Every spawn prompt carries six fields — a bare one-line task is never enough:

| Field | Content |
|-------|---------|
| GOAL | the overall task and why it exists — the point beyond the file edit |
| ROLE | what this agent owns; what it must NOT touch |
| SCOPE | exact paths/commands in bounds + explicit out-of-bounds |
| CONTEXT | what is already done, by whom, what runs in parallel — trimmed to what THIS agent needs |
| CONSUMER | who or what uses the result next, and the shape it must fit |
| DONE | acceptance criteria + the exact report shape you want back |

The same brief lives in E2E references, convention-setup's rules guide, teams-setup's roster
template and superreview-setup's emitted template. Main owns spawns and integration; delegates
return decisions and results rather than nesting.

Agents and skills management default to read-only status. Their prompt-first contracts use
existing answers, resolve explicit modes anywhere in the prompt, and bundle unresolved write
decisions into one pre-write question. Creator references follow current Claude Code contracts
checked through 2.1.285; structural validation and live evaluation provide different evidence.

## Lifecycle

The recommended skill execution order for a standard project cycle:

<Steps>
  <li>
    <div>
      <strong>Setup status</strong>
      <p>Start here on an unfamiliar repo: one read-only table of what is already installed, stale or missing, with the exact command per row. <a href="/brewcode/skills/setup-status/">setup-status</a></p>
    </div>
  </li>
  <li>
    <div>
      <strong>Search foundation</strong>
      <p>Inspect or install semantic search when applicable. <a href="/brewcode/skills/semble-setup/">semble-setup</a></p>
    </div>
  </li>
  <li>
    <div>
      <strong>Convention foundation</strong>
      <p>Capture coding, testing and architecture patterns before generating agents. <a href="/brewcode/skills/convention-setup/">convention-setup</a></p>
    </div>
  </li>
  <li>
    <div>
      <strong>Teams setup</strong>
      <p>Create project domain agents using those conventions. <a href="/brewcode/skills/teams-setup/">teams-setup</a></p>
    </div>
  </li>
  <li>
    <div>
      <strong>Superreview setup</strong>
      <p>Generate a per-project deep-review skill tailored to your tech stack and agents. <a href="/brewcode/skills/superreview-setup/">superreview-setup</a></p>
    </div>
  </li>
  <li>
    <div>
      <strong>Rules</strong>
      <p>Sync learned knowledge to project rules for future sessions. <a href="/brewcode/skills/rules/">rules</a></p>
    </div>
  </li>
</Steps>

<Callout type="tip" title="Skill Management">
  Use <a href="/brewcode/skills/skills/">/brewcode:skills</a> to list, create, improve, or sync (delete-first, non-growth).
  The <a href="/brewcode/agents/skill-creator/">Skill Creator</a> agent handles the creation process.
</Callout>

## Skill dependencies

```
setup-status  (read-only: what is already here)
      |
semble-setup  (search foundation, when applicable)
      |
convention-setup  (coding, architecture and testing foundation)
      |
teams-setup --> project domain agents
      |
superreview-setup --> /superreview (emitted into your repo)

rules / skills / agents / e2e remain recurring tools
```

<Callout type="note" title="Dynamic teams">
  <code>/brewcode:teams-setup install</code> creates 5-20 project-specific agents with a self-selection protocol,
  performance tracking, and automatic tuning. Run <code>/brewcode:teams-setup upgrade</code> later to tune
  underperformers from the recorded trace data.
</Callout>
