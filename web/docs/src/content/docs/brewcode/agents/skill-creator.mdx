## Quick reference

| Field | Value |
|-------|-------|
| Agent | `brewcode:skill-creator` |
| Triggers | create skill, improve skill, fix activation |
| Model | inherit: uses the session model |
| Output | Skill directory, artifact list, validator and evaluation results, open questions |

Skill Creator turns a proven workflow into a reusable Claude Code skill, improves an existing one, or applies confirmed review findings. It follows the closest well-built skill in the repository, writes `SKILL.md` plus only the references and scripts the workflow needs, then validates and evaluates the result.

## When to use

- Capture a proven workflow as a reusable skill.
- Add a skill with deterministic scripts and supporting references.
- Fix wrong frontmatter, tool assumptions, or invocation behavior.
- Apply independently confirmed review findings to a skill.

## Example

```text
Create one project skill for database migrations. Own .claude/skills/db-migration/.
Follow the existing migration workflow and project test commands. Require explicit
invocation; return artifact paths, validator verdict, and output-evaluation evidence.
```

Expected result: a `SKILL.md` and the needed references, scripts and tests. Logs stay in a report file; the return names written artifacts, validation results, and unresolved decisions.

## How it works

<Steps>
  <li><div><strong>Resolve scope</strong><p>Extract the workflow from the brief and pick the project, personal, or plugin location.</p></div></li>
  <li><div><strong>Choose invocation</strong><p>Apply the invocation policy and decide between forked and inline execution.</p></div></li>
  <li><div><strong>Write</strong><p>Free-text prompt entry point, a PLAN block before actions, details in references loaded on demand.</p></div></li>
  <li><div><strong>Validate and evaluate</strong><p>Run <code>validate-skill.sh</code>, then test three to five realistic prompts against fresh-session baselines.</p></div></li>
  <li><div><strong>Hand back</strong><p>Return paths to the main caller, which runs <code>brewtools:text-optimize</code> on them.</p></div></li>
</Steps>

It refuses briefs over about 5 files or 10 steps and returns a split proposal. It does not spawn agents or run its own optimization; the main caller does ([delegation](/brewcode/skills/#delegation)). Generic refusals: [scope guard](/brewcode/agents/#scope-guard).

<Spoiler id="invocation-policy" title="Invocation policy">

| Context | Configuration |
|---------|---------------|
| Distributed Brewcode product skill | `user-invocable: true` and `disable-model-invocation: true` (exceptions: `brewdoc:publish`, `brewtools:text-optimize`, `brewtools:text-human`, each `disable-model-invocation: false`) |
| User-only skill outside distributed products | `disable-model-invocation: true` |
| Model-only knowledge outside distributed products | `user-invocable: false` |
| Both paths outside distributed products | Default behavior |

The distributed-product rule is repository policy, stricter than upstream defaults. Evaluate output through explicit invocation; Claude Code publishes no automatic-activation percentage.

</Spoiler>

<Spoiler id="execution-and-tools" title="Execution and tools">

- A skill with `context: fork` starts an ordinary subagent, not a conversation fork: tools are filtered and `AskUserQuestion` is unavailable.
- The agent carries no `Agent` tool; split and optimization requests go back to the caller.
- `allowed-tools` preapproves calls; it is not a sandbox. Grants clear on the next user message, skill instructions persist.
- Scope permissions to the needed calls. Bare `Bash`, `Write` or `Edit` fits only a user-invoked skill with open-ended shell or write paths.
- `${CLAUDE_SKILL_DIR}` is a load-time substitution, not an environment variable for hooks or agents.
- A `hooks:` block in `SKILL.md` stays registered for the rest of the session, so declare it only for behavior that must always hold; a one-shot hook takes `once: true` on the hook entry. A hook command is not substituted: write `"$CLAUDE_PLUGIN_ROOT/..."` or `${CLAUDE_PROJECT_DIR}`, never `${CLAUDE_SKILL_DIR}` or the braced plugin-root token.

</Spoiler>

<Spoiler id="validation-and-references" title="Validation and references">

The bundled validator checks frontmatter, naming, prompt contract and structure; a pass complements evaluation but does not prove the workflow works. Confirmed fixes need another run.

References under `brewcode/skills/skills/references/` hold the frontmatter catalog, execution model, design patterns, activation troubleshooting, prompt contract and review checklist, refreshed through Claude Code 2.1.296. The agent checkpoints artifact paths in its report directory; `maxTurns` is a loop stop, so partial work resumes from evidence.

</Spoiler>
