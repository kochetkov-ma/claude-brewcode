# Brewcode Overview

Brewcode is a Claude Code authoring toolkit: skills (recipes) define what to brew, agents (brewers) do the work, hooks (processes) handle session start and recovery after compaction.

## What you get

|------|--------------|------|
| `setup-status` | Dashboard of 11 setups and 23 stamp carriers across brewcode, brewtools, brewdoc; `upgrade` brings the stale ones current | [Skill](/brewcode/skills/setup-status/) |

## How it fits

Brewcode layers on top of Claude Code with no external runtime. Skills spawn agents, agents write rules and project files, and the two SessionStart hooks keep sessions anchored. Generic implementation and review roles are generated per project into `.claude/agents/` by [`/brewcode:teams-setup`](/brewcode/skills/teams-setup/). The [brewcode mods](/mods/overview/) add prompt placeholders and plan-mode effort.

## Technical details

<Spoiler id="naming" title="Naming: -setup vs bare">

A **`-setup`** skill installs a mechanism (agents, hooks, a rule, a generated skill) that you then use. Run it once, `upgrade` it later. Bare-named skills are recurring tools. Every setup answers `status`, `install`, `upgrade`, `enable`, `disable`, `uninstall`, `purge`. A bare call means status when installed and install when absent; [`semble-setup`](/brewcode/skills/semble-setup/) and the four brewtools guard setups (manager, agent-deadline, agent-return, agent-router) always default to status, [`convention-setup`](/brewcode/skills/convention-setup/) to install. Full rule: [Skills](/brewcode/skills/).

</Spoiler>

<Spoiler id="artifact-metadata" title="Artifact metadata">

Every artifact a `-setup` skill installs carries the same stamp across brewcode, brewtools and brewdoc. The version always comes from `.claude-plugin/plugin.json`, never hardcoded and never the literal `unknown`: a writer that cannot resolve it refuses to write.

| Field | Values | Where |
|-------|--------|-------|
| `doc_type` | `llm` \| `user` \| `skip`, unquoted | `.md` frontmatter only, never JSON |
| `version` | quoted `"X.Y.Z"`, plugin version at install | every carrier |
| `content_version` | quoted `"X.Y.Z"`, last release that changed the content | every carrier |
| `generated_by` | quoted `"<plugin>:<skill>"` | every carrier |
| `last_updated` | quoted `"YYYY-MM-DD"` | every carrier except a byte-copied `.mjs`/`.sh`/`.md` (the date would churn the drift check) |

| Carrier | Applies to |
|---------|-----------|
| JSON top-level keys | JSON artifacts |
| `.md` frontmatter | generated `.md` skills and docs |
| `// brewcode-meta:` one-liner, line 2 | byte-copied `.mjs`/`.sh` |
| header table (`\| Version \|`, `\| Generated by \|`, `\| Last update \|`) | `team.md` |
| `<!-- brewcode-meta: ... -->`, line 1 | byte-copied `.md` |

[`/brewcode:setup-status`](/brewcode/skills/setup-status/) reads the stamps back and flags any artifact whose `content_version` is behind the plugin. One skill's full contract: [`superreview-setup`](/brewcode/skills/superreview-setup/#version-and-ownership).

</Spoiler>

<Spoiler id="plugin-structure" title="Plugin structure">

```
brewcode/
├── .claude-plugin/plugin.json   # manifest
├── hooks/                       # hooks.json, session-start.mjs, compact-recall.mjs, lib/utils.mjs
├── agents/                      # 7 agents (5 public + 2 internal: bc-rules-organizer, setup-upgrader)

└── templates/                   # rule templates
```

Full tree: [file-tree.md](https://github.com/kochetkov-ma/claude-brewcode/blob/main/brewcode/docs/file-tree.md).

</Spoiler>

<Spoiler id="agents-and-contracts" title="Agent contracts and tests">

Creator agents and their on-demand references follow Claude Code authoring contracts checked through 2.1.296. They distinguish ordinary agents, conversation forks and skill forks, and return unresolved decisions to the main caller. Local regression suites cover creator contracts, hooks, team lifecycle, convention lifecycle and semantic search; each prints current pass/fail totals, and none replaces a live evaluation.

</Spoiler>
