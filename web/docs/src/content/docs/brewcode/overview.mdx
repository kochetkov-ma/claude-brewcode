# Brewcode Overview

Brewcode is a Claude Code authoring toolkit: skills (recipes) define what to brew, agents (brewers) do the work, hooks (processes) handle session start and recovery after compaction.

## What you get

| Part | What it does | Page |
|------|--------------|------|
| `setup-status` | Read-only dashboard: 11 setups and 23 stamp carriers across brewcode, brewtools, brewdoc | [Skill](/brewcode/skills/setup-status/) |
| `semble-setup` | Semantic code-search MCP: install, audit, reindex | [Skill](/brewcode/skills/semble-setup/) |
| `convention-setup` | Coding, testing and architecture conventions with reversible loading | [Skill](/brewcode/skills/convention-setup/) |
| `teams-setup` | Dynamic project agent teams (5-20) with tracing and tuning | [Skill](/brewcode/skills/teams-setup/) |
| `superreview-setup` | Generates a project-tailored deep-review skill | [Skill](/brewcode/skills/superreview-setup/) |
| `rules`, `skills`, `agents`, `e2e` | Recurring tools: rules, skill and agent management, E2E tests | [All skills](/brewcode/skills/) |
| 6 agents | skill-, agent-, hook-, mod-creator, bash-expert, internal bc-rules-organizer | [Agents](/brewcode/agents/) |
| 2 hooks | `session-start` and `compact-recall` (plan, intent, task graph after compaction) | [Hooks](/brewcode/hooks/) |

## How it fits

Brewcode layers on top of Claude Code with no external runtime. Skills spawn agents, agents write rules and project files, and the two SessionStart hooks keep sessions anchored. Generic implementation and review roles are generated per project into `.claude/agents/` by [`/brewcode:teams-setup`](/brewcode/skills/teams-setup/). Optional [brewcode mods](/mods/overview/) add plan-mode effort and prompt placeholders.

<Callout type="caution" title="One setup per session">
  Every `-setup` skill is an interactive generator that fans out subagents and asks real questions. Two in one session degrade each other, so `setup-status` reports and stops. Run setups one at a time, ideally in a fresh session.
</Callout>

## Technical details

<Spoiler id="naming" title="Naming: -setup vs bare">

A **`-setup`** skill installs a mechanism (agents, hooks, a rule, a generated skill) that you then use. Run it once, `upgrade` it later. Bare-named skills are recurring tools. Every setup answers `status`, `install`, `upgrade`, `enable`, `disable`, `uninstall`, `purge`. A bare call means status when installed and install when absent; [`semble-setup`](/brewcode/skills/semble-setup/) always defaults to status, [`convention-setup`](/brewcode/skills/convention-setup/) to install. Full rule: [Skills](/brewcode/skills/).

</Spoiler>

<Spoiler id="artifact-metadata" title="Artifact metadata">

Every artifact a `-setup` skill installs carries the same stamp across brewcode, brewtools and brewdoc. The version always comes from `.claude-plugin/plugin.json`, never hardcoded and never the literal `unknown`: a writer that cannot resolve it refuses to write.

| Field | Values | Where |
|-------|--------|-------|
| `doc_type` | `llm` \| `user` \| `skip`, unquoted | `.md` frontmatter only, never JSON |
| `version` | quoted `"X.Y.Z"`, plugin version at install | every carrier |
| `content_version` | quoted `"X.Y.Z"`, last release that changed the content | every carrier |
| `generated_by` | quoted `"<plugin>:<skill>"` | every carrier |
| `last_updated` | quoted `"YYYY-MM-DD"` | every carrier except a byte-copied `.mjs`/`.sh`/`.md` (the date would churn the drift check) |

| Carrier | Applies to |
|---------|-----------|
| JSON top-level keys | JSON artifacts |
| `.md` frontmatter | generated `.md` skills and docs |
| `// brewcode-meta:` one-liner, line 2 | byte-copied `.mjs`/`.sh` |
| header table (`\| Version \|`, `\| Generated by \|`, `\| Last update \|`) | `team.md` |
| `<!-- brewcode-meta: ... -->`, line 1 | byte-copied `.md` |

[`/brewcode:setup-status`](/brewcode/skills/setup-status/) reads the stamps back and flags any artifact whose `content_version` is behind the plugin. One skill's full contract: [`superreview-setup`](/brewcode/skills/superreview-setup/#version-and-ownership).

</Spoiler>

Full tree: [file-tree.md](https://github.com/kochetkov-ma/claude-brewcode/blob/main/brewcode/docs/file-tree.md).

</Spoiler>

<Spoiler id="agents-and-contracts" title="Agent contracts and tests">

Creator agents and their on-demand references follow Claude Code authoring contracts checked through 2.1.296. They distinguish ordinary agents, conversation forks and skill forks, and return unresolved decisions to the main caller. Local regression suites cover creator contracts, hooks, team lifecycle, convention lifecycle and semantic search; their output gives current pass/fail totals and does not replace live evaluation.

</Spoiler>
