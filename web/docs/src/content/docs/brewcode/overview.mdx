# Brewcode Overview

<InstallPrompt plugin="brewcode" mode="install" />

Install the entire suite:

<InstallPrompt plugin="all" mode="install" />

Brewcode is a plugin for Claude Code for spec authoring, multi-agent review, and a toolkit of
skills and agents. The name is a nod to brewing: skills (recipes) define what to brew, agents
(brewers) do the work, and hooks (processes) manage prompt-time injection.

## Key Features

## Architecture

Brewcode works as a layer on top of Claude Code through the hook system. The plugin has no external runtime --
all context is managed through built-in Claude Code events.

```
                         Brewcode Plugin
  ┌──────────────────────────────────────────────────────────┐
  │                                                          │
  │   Skills (recipes)            Agents (brewers)           │
  │   ┌──────────────┐          ┌──────────────────┐         │
  │   │ semble-setup │          │ skill/agent/hook  │         │
  │   │ superrev-... │ ──────>  │ creator, bash     │         │
  │   │ e2e, conv... │          │ + project teams   │         │
  │   └──────────────┘          └──────────────────┘         │
  │          │                          │                     │
  │          v                          v                     │
  │   Hooks (processes)           Templates + Knowledge      │
  │   ┌──────────────┐          ┌──────────────────┐         │
  │   │ session-start│          │ rules templates   │         │
  │   │ forced-eval  │ <──────> │ artifacts/        │         │
  │   │              │          │                   │         │
  │   │              │          │                   │         │
  │   └──────────────┘          └──────────────────┘         │
  │                                                          │
  └──────────────────────────────────────────────────────────┘
```

## Plugin structure

```
brewcode/
├── .claude-plugin/
│   └── plugin.json                    # Plugin manifest
├── hooks/
│   ├── hooks.json                     # 2 hooks (SessionStart, UserPromptSubmit)
│   ├── session-start.mjs              # Version-check, plan-symlink, permission tag
│   ├── forced-eval.mjs                # [ROLE] delegate + [SPLIT] bounded units
│   └── lib/
│       └── utils.mjs                  # I/O, version cache, configuration
├── agents/                            # 5 agents
│   ├── skill-creator.md               # Skill creation (opus)
│   ├── agent-creator.md               # Agent creation (opus)
│   ├── hook-creator.md                # Hook creation (opus)
│   ├── bash-expert.md                 # Bash scripts (opus)
│   └── bc-rules-organizer.md          # Rules organizer (haiku)
├── skills/                            # 9 skills
│   ├── semble-setup/                  # Semantic code search MCP
│   ├── convention/                    # Convention analysis
│   ├── rules/                         # Rule extraction
│   ├── superreview-setup/             # Multi-agent quorum review generator
│   ├── setup-status/                  # Read-only cross-plugin setup dashboard
│   ├── skills/                        # Skill management
│   ├── agents/                        # Agent management
│   ├── teams-setup/                   # Dynamic agent teams
│   └── e2e/                           # E2E testing orchestration
└── templates/                         # Rule templates
```

## Naming: `-setup` vs bare

<Callout type="tip" title="The suffix tells you how often to run it">
A **`-setup`** skill installs a mechanism — agents, hooks, a rule, a generated skill — that you then use *instead of* the skill itself. Run it once, `upgrade` it when the plugin moves on. A **bare-named** skill is a recurring tool you run again and again, leaving no installed state behind. Every `-setup` skill answers the same seven verbs in this order: `status`, `install`, `upgrade`, `enable`, `disable`, `uninstall`, `purge`. Bare invocation means `status` when installed, `install` when not — except [`semble-setup`](/brewcode/skills/semble-setup/), which always defaults to `status` because its install reaches outside the project.
</Callout>


## Components in detail

<Tabs>
  <TabItem label="Skills">
    9 skills (recipes) cover search, review, conventions, and meta-tooling.
    See [Skills](/brewcode/skills/) for details.

    | Group | Skills | Purpose |
    |-------|--------|---------|
    | Search | semble-setup | Semantic code-search MCP install and maintenance |
    | Quality | superreview-setup, convention, rules | Multi-agent review, conventions, rule extraction |
    | Dynamic | teams-setup | Agent team creation and management |
    | Testing | e2e | E2E testing orchestration with BDD scenarios |
    | Meta | skills, agents | Skill and agent management |
    | Dashboard | setup-status | Read-only: what is installed, stale or missing across all four plugins |
  </TabItem>
  <TabItem label="Agents">
    5 agents (brewers), all specialists. Generic implementation/review roles are generated per project
    into `.claude/agents/` by [/brewcode:teams-setup](/brewcode/skills/teams-setup/) — brewcode no longer ships them.
    See the [Agents](/brewcode/agents/) section for details.

    | Role | Agents | Model |
    |------|--------|-------|
    | Creation | skill-creator, agent-creator, hook-creator | inherit |
    | Scripting | bash-expert | inherit |
    | Internal | bc-rules-organizer | haiku |

    + dynamic project agents created by [`/brewcode:teams-setup`](/brewcode/skills/teams-setup/)
  </TabItem>
  <TabItem label="Hooks">
    2 hooks manage prompt-time injection and session start.
    See the [Hooks](/brewcode/hooks/) section for details.

    | Event | Hook | Purpose |
    |-------|------|---------|
    | SessionStart | session-start | Initialization, version-check |
    | UserPromptSubmit | forced-eval | Manager-role + split-discipline reminder |
  </TabItem>
</Tabs>

## Quick start

<Steps>
  <li class="step step-primary">
    <div>
      <strong>See what is already here</strong> <Badge variant="primary" text="/brewcode:setup-status" />
      <p>Read-only. One table of every setup skill across brewcode, brewtools and brewdoc: installed, stale, partial, missing — plus the exact command for each row. Writes nothing.</p>
    </div>
  </li>
  <li class="step step-primary">
    <div>
      <strong>Conventions</strong> <Badge variant="primary" text="/brewcode:convention" />
      <p>Parallel per-layer analysis. Writes etalon classes and recurring patterns into <code>.claude/convention/</code>.</p>
    </div>
  </li>
  <li class="step step-primary">
    <div>
      <strong>Deep review</strong> <Badge variant="primary" text="/brewcode:superreview-setup install" />
      <p>Generate a project-tailored quorum review skill. Run once per project, then <code>upgrade</code> it.</p>
    </div>
  </li>
  <li class="step step-secondary">
    <div>
      <strong>Team install (optional)</strong> <Badge variant="secondary" text="/brewcode:teams-setup install" />
      <p>Install a project-specific agent team with performance tracking.</p>
    </div>
  </li>
</Steps>

<Callout type="caution" title="One setup per session">
  Every `-setup` skill is an interactive generator: it fans out subagents, analyses the repo and asks you real questions. Two in one session degrade each other — the second answers against the first one's stale analysis. Run them one at a time, ideally in a fresh session each. That is exactly why `setup-status` reports and stops instead of running anything.
</Callout>
