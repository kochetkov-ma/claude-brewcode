# Brewcode Overview

<InstallPrompt plugin="brewcode" mode="install" />

Install the entire suite:

<InstallPrompt plugin="all" mode="install" />

Brewcode is a plugin for Claude Code for spec authoring, multi-agent review, and a toolkit of
skills and agents. The name is a nod to brewing: skills (recipes) define what to brew, agents
(brewers) do the work, and hooks (processes) manage prompt-time injection.

## Key Features

<CardGrid>
  <Card title="Native plugin paths" icon="infinity">
    Agents resolve paths via native `${CLAUDE_PLUGIN_ROOT}`, substituted in each agent .md at Task spawn.
    No hook injection, no shared runtime state.
  </Card>
  <Card title="8 skills (recipes)" icon="terminal">
    From convention analysis (<a href="/brewcode/skills/convention/">/brewcode:convention</a>) and agent teams
    (<a href="/brewcode/skills/teams/">/brewcode:teams</a>) to multi-agent review (<a href="/brewcode/skills/superreview/">/brewcode:superreview</a>).
  </Card>
  <Card title="5 agents (brewers)" icon="users">
    Specialists only: [skill-creator](/brewcode/agents/skill-creator/), [agent-creator](/brewcode/agents/agent-creator/),
    [hook-creator](/brewcode/agents/hook-creator/), [bash-expert](/brewcode/agents/bash-expert/), and the internal bc-rules-organizer.
    Generic roles are generated per project into .claude/agents/.
  </Card>
  <Card title="2 hooks (processes)" icon="settings">
    Prompt-time delegation reminder and session-start version-check.
  </Card>
  <Card title="E2E testing" icon="check">
    BDD scenario authoring and Playwright autotest orchestration
    via <a href="/brewcode/skills/e2e/">/brewcode:e2e</a>.
  </Card>
  <Card title="Code quality" icon="shield">
    Standards-review, convention analysis.
    Rules are automatically synced to .claude/rules/.
  </Card>
  <Card title="Dynamic teams" icon="group">
    Create project-specific agent teams (5-20) with self-selection,
    performance tracking, and automatic tuning.
  </Card>
</CardGrid>

## Architecture

Brewcode works as a layer on top of Claude Code through the hook system. The plugin has no external runtime --
all context is managed through built-in Claude Code events.

```
                         Brewcode Plugin
  ┌──────────────────────────────────────────────────────────┐
  │                                                          │
  │   Skills (recipes)            Agents (brewers)           │
  │   ┌──────────────┐          ┌──────────────────┐         │
  │   │ semble, e2e  │          │ skill/agent/hook  │         │
  │   │ superreview  │ ──────>  │ creator, bash     │         │
  │   │ convention,. │          │ + project teams   │         │
  │   └──────────────┘          └──────────────────┘         │
  │          │                          │                     │
  │          v                          v                     │
  │   Hooks (processes)           Templates + Knowledge      │
  │   ┌──────────────┐          ┌──────────────────┐         │
  │   │ session-start│          │ rules templates   │         │
  │   │ forced-eval  │ <──────> │ artifacts/        │         │
  │   │              │          │                   │         │
  │   │              │          │                   │         │
  │   └──────────────┘          └──────────────────┘         │
  │                                                          │
  └──────────────────────────────────────────────────────────┘
```

## Plugin structure

```
brewcode/
├── .claude-plugin/
│   └── plugin.json                    # Plugin manifest
├── hooks/
│   ├── hooks.json                     # 2 hooks (SessionStart, UserPromptSubmit)
│   ├── session-start.mjs              # Version-check, plan-symlink, permission tag
│   ├── forced-eval.mjs                # [ROLE] delegate + [SPLIT] bounded units
│   └── lib/
│       └── utils.mjs                  # I/O, version cache, configuration
├── agents/                            # 5 agents
│   ├── skill-creator.md               # Skill creation (opus)
│   ├── agent-creator.md               # Agent creation (opus)
│   ├── hook-creator.md                # Hook creation (opus)
│   ├── bash-expert.md                 # Bash scripts (opus)
│   └── bc-rules-organizer.md          # Rules organizer (haiku)
├── skills/                            # 8 skills
│   ├── semble/                        # Semantic code search setup
│   ├── convention/                    # Convention analysis
│   ├── rules/                         # Rule extraction
│   ├── superreview/                   # Multi-agent quorum review
│   ├── skills/                        # Skill management
│   ├── agents/                        # Agent management
│   ├── teams/                         # Dynamic agent teams
│   └── e2e/                           # E2E testing orchestration
└── templates/                         # Rule templates
```


## Components in detail

<Tabs>
  <TabItem label="Skills">
    8 skills (recipes) cover search, review, conventions, and meta-tooling.
    See [Skills](/brewcode/skills/) for details.

    | Group | Skills | Purpose |
    |-------|--------|---------|
    | Search | semble | Semantic code-search MCP setup and maintenance |
    | Quality | superreview, convention, rules | Multi-agent review, conventions, rule extraction |
    | Dynamic | teams | Agent team creation and management |
    | Testing | e2e | E2E testing orchestration with BDD scenarios |
    | Meta | skills, agents | Skill and agent management |
  </TabItem>
  <TabItem label="Agents">
    5 agents (brewers), all specialists. Generic implementation/review roles are generated per project
    into `.claude/agents/` by [/brewcode:teams](/brewcode/skills/teams/) — brewcode no longer ships them.
    See the [Agents](/brewcode/agents/) section for details.

    | Role | Agents | Model |
    |------|--------|-------|
    | Creation | skill-creator, agent-creator, hook-creator | inherit |
    | Scripting | bash-expert | inherit |
    | Internal | bc-rules-organizer | haiku |

    + dynamic project agents created by [`/brewcode:teams`](/brewcode/skills/teams/)
  </TabItem>
  <TabItem label="Hooks">
    2 hooks manage prompt-time injection and session start.
    See the [Hooks](/brewcode/hooks/) section for details.

    | Event | Hook | Purpose |
    |-------|------|---------|
    | SessionStart | session-start | Initialization, version-check |
    | UserPromptSubmit | forced-eval | Manager-role + split-discipline reminder |
  </TabItem>
</Tabs>
