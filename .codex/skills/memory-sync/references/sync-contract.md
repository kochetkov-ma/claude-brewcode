# Project instruction sync contract

## Inventory, baseline, and authority

Start with the user's requested edit boundary, then discover native instruction candidates using `rg --files --hidden` and targeted filesystem probes. Git-ignored instruction files may still be authorized; git status alone is not an inventory. Record exact path, real path, instruction type, edit/verify-only/excluded status, reason, bytes/lines/hash, and owner. Use files actually present, not stamped counts. Do not traverse secret files, runtime databases, caches, or unrelated profiles.

Classify distributed product/template sources separately from installed project instructions even if both contain `SKILL.md` or TOML. Source/template differences are read-only evidence and proposals. `AGENTS.md` nested in examples, fixtures, temporary clones, build output, or foreign products is not project instruction authority. Claude surfaces, symlinks to shared/external files, and personal/global layers are verify-only; report needed changes at their canonical source. Never copy auth or runtime state. Refuse writes through an ambiguous real-path boundary until the edit target is known; continue independent authorized work.

Snapshot every authorized edit file before mutation, plus verify-only boundaries needed to check preservation, in the current task's report/temp area. Preserve raw content for ignored/untracked files whose originals Git cannot recover. Do not populate snapshots with credentials, secret values, or unrelated histories. Missing/new-file proposals are separate from the existing-file baseline. Record hashes so final changes can be attributed without treating concurrent writers' changes as this task's edits. Re-read before patching; coordinate collisions rather than reverting.

Session facts come from actual conversation changes; do not invent a gather step if context suffices. Branch facts use the merge base with the live default branch; commit/range uses the selected revision; recent defaults to ten commits but degrades safely for short history. `all` re-verifies all checkable facts inside the authorized inventory, not every file in the repository. User exclusions/path restrictions remain binding under every mode/depth.

## Fact checks and canonical homes

For each factual claim, record its instruction location, authoritative source/command, observed result, and verified/stale/uncertain verdict. Check commands, module paths, rule references, agent ownership/runtime availability, hooks, native metadata, and behavior against the actual producer. Read config keys as needed without exposing secret values; config remains read-only. Missing authentication/tools/evidence means uncertain, not false. User decisions and prohibitions are authority: do not delete them because code currently violates them. Preserve unresolved claims and report why they could not be verified.

Choose the narrowest canonical instruction home that reaches every consumer: root orientation in root `AGENTS.md`; subtree facts in nested `AGENTS.md`; constraints in explicitly referenced rules; role ownership/output in agent TOML; procedures in skills; conventions only when they are actually referenced. On equal scope prefer the existing authoritative home. Replace duplicates with pointers that resolve and are explicitly loaded when needed; do not leave a pointer plus a restatement. Narrower exceptions and overrides are not duplicates. Cross-owner moves require coordination, and moves outside the authorized set are proposals only.

Persistent personal memories are a different policy-controlled surface. Without a direct explicit request do not add, move, delete, or update them. With a request first read and obey the active memory policy, including allowed destination/update-note mechanism, durable-knowledge criteria, and citation requirements. This skill never bypasses that policy or chooses a new memory directory.

## Editing and compactness

Correct stale facts before deduplication; deduplicate before compression. Use `apply_patch` on authorized files only. Preserve semantics of must/must-not, default/only/all/regardless, conjunctions, scope, exceptions, trigger conditions, user choices, links, stable rule numbers, and provenance. Never hand-bump generator-owned versions or change an internal-only agent into an auto-triggered one. Explain a disputed authority instead of silently replacing it.

Prefer non-growth per file and across the inventory: delete obsolete or duplicated claims before adding replacements. Compactness does not justify deleting a verified constraint or retaining a false fact. If an essential correction, supported native metadata, or explicit loader/index repair needs growth, make the smallest authorized change and report its reason and delta; do not add unrelated material to consume a budget. Do not auto-create agents, rules, skills, global instructions, or memories.

Audit included agent TOML for valid native structure, live role availability, precise responsibilities, boundaries, output contracts, tool capability claims, model routing against active policy, and resolving references. Audit skill YAML for supported name/description, useful selection boundaries, native tools, scope/mutation contracts, progressive references, and usable procedures. Runtime availability cannot be inferred merely from a TOML file; report unverified fresh-session loading. No YAML extraction from TOML and no Claude-only tool names as native runtime instructions.

HARD: remove generic tutorials/platitudes and redundant explanations while retaining concrete decisions, failure-prevention facts, overrides, and prohibitions. Ambiguous project-specific knowledge stays with an uncertainty note. Inspect any declared `paths:` for actual matches and intended scope using tracked files plus targeted filesystem probes, including ignored authorized paths; classify valid/too-broad/too-narrow/dangling/global. `paths:` is metadata, not Codex autoload. Verify explicit root/nested instruction or skill references and maintain the root `Rule | Load when | Purpose` index for authorized rule changes. If the index is outside scope, leave it unchanged and report the exact pending correction. Follow applicable text-optimization instructions after rule/index edits without expanding scope.

## Independent verification and closeout

Each owner returns edited paths, exact fact evidence, deletions/moves with reasons and original text/location, before/after lines/bytes, preserved decisions, and uncertainties. An independent checker receives the request, original snapshots, current files, and raw fact sources; it verifies facts and deletions itself rather than accepting the writer's verdict. Confirm boundary preservation, new real paths/symlinks, reference resolution, native TOML/YAML validity, loader/index correctness, provenance, rule IDs, semantic scope/negation, and size deltas. Re-read full originals/current files when reduced below half; check lost exceptions and instruction applicability.

Compare final hashes to snapshots and each owner's declared edits. Undeclared/excluded changes require attribution: distinguish concurrent work from this task's violation, never revert either silently. Confirm verify-only files stayed byte-identical relative to this task's activity. A second coordinator pass is useful when independent checking is unavailable, but label it honestly; unresolved material verification makes the sync incomplete. Resolve discrepancies inside the authorized set and recheck affected files only.

Finish with concrete edited paths and sizes, confirmed corrections/deduplication, uncertain facts retained, scope/exclusion compliance, verify-only/source/global drift proposals, actual checks and limits. Self-correction follows the same explicit inventory boundary: no mandatory self-sync, hidden writes, source repairs, public-doc updates, or persistent-memory changes. Use a current task report under `.codex/reports/` when an artifact is needed; that report is not future instruction memory.
